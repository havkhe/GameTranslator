RPG Maker 汉化管理器（GameTranslator.exe） v2.4
==============================================

【v2.4 更新说明 —— 修复"断点续翻"、"已汉化"误判，以及"卡住"问题】
  - 抽取范围修正（重要）：以前只扫描 data 目录**根层**的 json，且只认
    name/description/message1… 这些固定字段名。实测发现不少多语言 MZ 游戏把
    **全部剧本**放在 data\resources\<语言>\*.json（用插件自己的键名，
    如 Hiroka_HEV1_000、SYSTEM_TITLE_ITEM_NEWGAME），旧版会**一条都抽不到**，
    于是"汉化完成但游戏里还是日文"。现在：
      · 递归扫描 data 下所有子目录（含 resources\<语言>\、js\plugins\ 等）；
      · resources 下的文件按"显示文本"处理，所有字符串值都是候选，
        但 metadata（语言/游戏名）块、素材路径、纯 ASCII 标识符**不动**；
      · 抽取与回写共用同一份文件清单，扫到的文件就是会被写回的文件。
    实测某游戏：抽取 2809 → 9323 条（另一款 12 714 条，其中 8953 条来自
    resources）；英文语系（en-US）、备份目录（如 バックアップ、备份）不翻。
  - 抽取覆盖扩大（MV/MZ 与 VX Ace 同步）：
      · MV/MZ 新增 message3/message4、displayName、currencyUnit、title、
        terms.hint 等字段，以及运行中改名指令 320/324/325；
      · 插件参数里的显示文本也会翻译（data\plugins.js 等），插件标识符与
        <Icon: 5> 这类 ASCII 标记原样保留；
      · VX Ace 新增 @note 与 @display_name；
      · 数据库的 note 字段（MV/MZ）**故意不翻**：插件会把它当元数据解析，
        翻译会破坏插件功能。
  - 本工具**支持的游戏类型**（其余类型目前无法处理，会在日志里说明）：
      · 支持：RPG Maker MV / MZ（含 www\data 与根目录 data 两种布局）、
        RPG Maker VX Ace（Data\*.rvdata2，或未解包的 Game.rgss3a 自动解包）
      · 不支持：RPG Maker VX（Data\*.rvdata / Game.rgss2a）、
        RPG Maker XP（*.rxdata / Game.rgssad）、RPG Maker 2000/2003、
        Wolf RPG（data.wolf）、Unity 等非 RPG Maker 引擎
      · MV/MZ 新增 message3/message4、displayName、currencyUnit、title、
        terms.hint 等字段，以及运行中改名指令 320/324/325；
      · 插件参数里的显示文本也会翻译（data\plugins.js 等），插件标识符与
        <Icon: 5> 这类 ASCII 标记原样保留；
      · VX Ace 新增 @note 与 @display_name；
      · 数据库的 note 字段（MV/MZ）**故意不翻**：插件会把它当元数据解析，
        翻译会破坏插件功能。
  - 新增术语表（可选）：在游戏目录放 glossary.txt（或 work\glossary.txt），
    每行写 `原文->译文`，# 后面是注释。术语会同时：
      · 追加到提示词里让模型参考；
      · 在译文里**强制替换**（长词优先），保证同一人名/专有名词全篇一致。
  - 新增翻译质检层：控制符/占位符丢失、残留日文占优、乱码或错误语种、
    复读退化（同一字符刷屏）、译文被截断、原文原样返回 —— 这些**不会写进游戏**，
    会走拆批重试；重试仍失败则记入 failures.json 并保留原文，下次继续。
    另外"译文过长、换行数变化、新出现括号不配对、零星假名"只作为复核提示。
  - "检查翻译"结果分三档：必须重翻（fatal）/ 建议复核（suspect）/ 未翻译（pending），
    对话框中会分别显示；重翻时**保留已有译文，只在结果更好时替换**。
  - 修复"检查翻译"的对照基准：以前是拿译文和"游戏当前文件"比，游戏已汉化时
    文件本身就是中文，等于中文对中文、结论没有意义；现在改为与 data_原版备份 里的
    原始日文对照（加密包也会解包），并报告实际对照了多少条。
  - 【模型选择建议 · 本机 GTX 1060 实测】同一份 126 条真实日文：
      · Qwen3.5-0.8B-Q4_K_M：**不可用**，0 条可用译文（连单条兜底也失败），
        请勿用于汉化；
      · Hy-MT2-1.8B-Q8_0：可用，约 90 秒完成 121/126 条（5 条失败），
        显存很小或追求速度时可用；
      · Galtransl-v4-4B-2601：**推荐**，约 80 秒完成 126/126 条、0 失败。
    注：短条目（道具/技能名）跑得快；剧情正文按 token 数线性变慢，
    4B 模型在本机约 37 token/s、平均约 0.4 秒/条。
  - 修复"软件像卡住"：模型陷入退化复读时，旧版只断开客户端、服务端仍在生成，
    后续重试全部排队堵在同一槽位。现在请求 45 秒无输出即判定卡死并中止，
    主动清空 llama 槽位；连续 3 次卡死直接停止本次运行（进度全部保留），
    实测卡死场景由"超过 104 秒仍未结束"变为"12 秒内干净退出"。
  - 生成长度按输入自动收敛（约为源文长度×2，上限 1024），
    旧版固定 2048，等于给复读留了空间。
  - 采样参数对齐模型作者推荐：temperature 0.3 / top_p 0.8 /
    frequency_penalty 0.1，llama 启动参数同步设置并默认开启 --metrics。
  - 默认提示词改为"逐行输出、不编号、不要JSON"，并自动补充官方 system 提示词；
    旧版保存的 JSON 提示词会被自动升级（手写自定义提示词不会被动）。
  - 修复严重问题：重新汉化同一个游戏时，之前会从"已被汉化的数据"里重新抽取
    原文，导致译文缓存完全命中不上、已翻译的几千条被反复重翻，
    甚至把自己的中文再翻一遍（越翻越乱）。现在改为：
      · 优先从 data_原版备份 读取原始日文作为翻译源；
      · 活动数据目录只用来补充"备份之后新增的内容"；
      · 同时按原文文本与历史译文双重过滤，绝不会再翻译自己的输出。
  - 译文缓存改为"按原文文本"存储（旧缓存自动迁移，进度不丢）：
      · 抽取规则升级、条目顺序变化后依然能续翻，不再整局重来；
      · “检查翻译”的"未翻译"数量不再是假的（以前会报几千条其实早已翻好）。
  - 单条超长文本（如 2000 字的连续台词）会按标点自动切成小段翻译再拼回，
    不会再因为一条长文本撑爆上下文而让整批 16 条一起失败。
  - 整批失败不再"原地重试 3 次"，改为对半拆批重试（16→8→4→…），
    一条坏文本不会再拖累同批的其它内容。
  - 新增机器可读报告：work\<游戏>-patch-report.json（回写条数、未匹配条数、
    每个文件的替换数与错误）与 work\<游戏>-translate-report.json。
  - 引擎识别修复：支持"没有 www 目录"的 NW.js 打包 MV/MZ 游戏。
  - “已汉化(跳过)”判定修复：不再仅凭存在 data_原版备份 就跳过
    （以前"卸载汉化"还原原版的游戏会被永久跳过）；VX Ace 的二进制数据
    不再按文本统计。
  - 说话人名字（MV/MZ 指令 101）现在也会被翻译；355/405 等脚本指令仍然
    绝对不会被翻译（避免改坏游戏逻辑）。
  - 还原脚本兼容两种布局：www\data 与"根目录 data\"。

一、支持的引擎
  - RPG Maker MV / MZ（www\data 下的 json 数据）
  - RPG Maker VX Ace（Data\*.rvdata2 散装数据，或加密包 Game.rgss3a，
    会自动解包 → 汉化 → 重新打包，并保留原版加密包备份）

二、模型
  - 模型为 GGUF 文件，默认从 D:\galtrans 加载（可改）。
  - 内置 llama.cpp Vulkan 版，自动使用独立显卡推理（GTX 10 系等老卡可用）。

三、使用方法
  1. 选择盘符点“扫描”，或“选择文件夹”/拖拽 Game.exe 加入游戏列表。
  2. 选择模型（自动列出模型目录中的 GGUF）。
  3. 点“开始汉化选中”或“全部汉化”；第一次会自动加载模型（等待就绪）。
  4. 汉化前自动备份：游戏目录下生成 data_原版备份 和“一键还原汉化前.bat”，
     出错时双击该 bat 或点“一键还原选中”即可恢复原版。
  5. 暂停 / 继续：批次间生效；终止：保存进度后停止，可断点续翻。
  6. 断点续翻：中断后重新对同一游戏执行汉化，会自动跳过已翻译的条目继续。
  7. 检查翻译：选中游戏点底部“检查翻译”，发现未翻译/翻译不全后可立即重翻。
  8. 底部“停止llama”可手动释放显存；“卸载汉化/恢复汉化”在原版与汉化版间切换。

四、说明
  - 已汉化（中文明显多于日文）的游戏会被自动跳过。
  - 非 RPG Maker 游戏不会被识别，也不会被改动。
  - 目录结构：GameTranslator.exe（界面）、game-pipeline.js（汉化管线）、
    llama\（内置 llama.cpp 运行时）、ruby\（便携 Ruby，处理 .rvdata2）、
    vxace_*.rb（VX Ace 数据读写）、rgss3a.js（Game.rgss3a 解包/重打包）。
  - 翻译进度保存在软件目录 work\<游戏名>-translations.json。
