# P13 —— 四局"没汉化成功"的成因与修复

对象：`pipeline/`、`ui/MainForm.cs`、`tools/unit-*`。
承接 `docs/P12-分组翻译队列.md`。起因：一次批次里 5 局游戏只有 1 局看起来成功。

批次：`NTR Police ver1.10`、`NTR Sisters - Ciella & Luciella`、`NTR Gyaru`、`deadbunny_1001`
（用户报告"没有汉化成功"）与 `(同人ゲーム)[静かな北国] 隙間時間に正義のお仕事`（"成功"）。

---

## 一、取证（不是推断）

| 检查 | 结果 |
| --- | --- |
| `work\*-patch-report.json` | 五局都写了文件（replaced 1874 / 1647 / 8 / 2291 / 18240） |
| `work\skips.log` | **只有 6 行，全是 00:30** —— 14:0x 那次批次没有任何"重试 3 次仍失败"记录 |
| `audit-game.js` | 那 4 局 **CLEAN**（没坏），"成功"的静かな北国反而 **423 处缺陷** |
| `game-state.js` | 五局全部 `已汉化（本项目）96–99%` |

所以**不是运行失败**，也不是数据被改坏。逐条实测后定位到四个不同的成因。

---

## 二、成因 A（deadbunny 的主因，也是最大的一处）：正文不在 `data/` 里，我们从没读过

`deadbunny_1001\scenario\Scenario.json` —— **20 MB**，**1,130 条剧本**，每条是一串 MV 事件指令，
`data` 里只有一个插件参数（`ファイル名 = オープニング_3行で_01`）指向它。整个故事都在这个文件里。

实测：

```
data 里含假名的事件参数      16 个        ← 我们只翻了这里
scenario/Scenario.json     42,757 条     ← 一条都没碰
```

所以 deadbunny 的 `patch-report` 里 `files: 28` 看着像成功，游戏玩起来却全是日文。

### 修复

新增 `pipeline/extract/scenario.js`：定位游戏根或 `www\` 下的 `scenario\` 目录，用**已有的 MV 遍历器**
（schema 完全一样，不需要新解析器）读写，并在写之前做 `scenario_原版备份` 快照。
只认字面名为 `scenario` 的目录 —— 更宽的"任何含指令 JSON 的目录"会连 `MTool_MapDataCache`、
`data_汉化备份` 一起扫进来。目录里**只有形如事件指令的 JSON 会被读写**（`"code":N` + `"parameters"`），
同目录的配置文件原样不动。

实测（`mode=extract`，只写工作目录、不改游戏数据）：

```
deadbunny_1001    SCENARIO 42757 entries from 1 file(s)   EXTRACTED 44865   （原来 1,951）
release_0429      SCENARIO 21089 entries from 1 file(s)   EXTRACTED 22322   （同款剧本插件）
NTR Gyaru         无 scenario 目录，TEXT2FRAME 68 条      EXTRACTED 88      （未变）
NTR Police        无 scenario 目录                        EXTRACTED 964     （未变）
```

全库只有这 2 局用这种存法（按"JSON 里含事件指令对象"逐局扫描确认）。

## 三、成因 B：汉字词被当成"已是中文"永久跳过

`translate/index.js` 用 `isChineseLike` 判断"这段已经是中文，不必翻"，判据是"没有假名 + 汉字过半"。
而日文游戏里最不缺的就是这种串：技能名、属性名、状态名、敌人名。

实测四局的 `already-chinese` 失败记录：

```
NTR Police 79/79、NTR Sisters 79/79、deadbunny 97/97、静かな北国 62/62
   全是「无假名、≤7 字」的日文术语
   例: 斬撃/必殺技3、刺突/必殺技1、爪/必殺技、回復/単体1、蘇生1、強化1、怪人王、神父、超音波、歌、咆哮
```

这些字符串**本来就已经被提取、被加入队列**（提取器的规则表明确写着"无假名也要保留，它常是真名字"），
却在翻译阶段被整组跳过；而且这个判定**不写入缓存**，所以每一次重跑都会被再跳过一次 —— 永不翻译。
结果是同一张菜单里一部分是中文、一部分是日文。

### 修复

`translate/index.js` 新增 `mayBeChineseAlready()`：**只有长度 ≥ 12 的汉字段落才按"已是中文"跳过**，
短术语一律送去翻译。保留原来那道保护（把中文送回模型会让它拒译并级联出上千条失败），
但不再误伤术语。`CHINESE_PROSE_MIN = 12` 可调，`isChineseLike` 本身未改动。

## 四、成因 C：与原文完全相同的"译文"进了缓存

四局缓存里 `值 == 原文` 的条目：**202 / 71 / 5 / 83 / 59** 条。

```
爪/物理 → 爪/物理      花粉 → 花粉      超音波 → 超音波      歌 → 歌      男 → 男
```

这种空操作会被 `patch` 计成 `replaced`，但磁盘上什么都没变 —— **NTR Gyaru 的报告就写着
`replaced 8, files 0`**：8 次"替换"、0 个文件被写。原因同 B：`quality.js` 的 `translatableSource`
要求**有假名**才认为该串"需要翻译"，于是无假名的术语绕过了"译文与原文相同"这条规则。

### 修复

- `quality.js`：`translatableSource` 改为"含任意 CJK 即算需要翻译"（原先只认假名），
  于是恒等译文被 `unchanged` 规则正常判死；
- `cache.js`：`badValue` 增加第 4 类 `identity`（`value === source`），加载时清除、`set()` 拒收，
  日志记 `CACHE_PURGED_IDENTITY`；`translate/index.js` 对被拒收的条目补记 `quality:refused` 失败，
  不再"既没缓存也没记录、下次又来一遍"。

## 五、成因 D：进度列读一个**没人写过**的文件

`MainForm.TryReadProgress` 读 `work\<名字>-translate-report.json`。实测：

- **没有任何组件写这个文件**（全仓库只有这一处读它）；
- 就算有人写，**名字也对不上**：窗口原来的推导是"保留字母数字与非 ASCII、其余丢掉"，
  而管线用 `[^a-zA-Z0-9\u4e00-\u9fff] → "_"` 且截断 60：
  `NTR Police ver1.10` → 窗口得 `NTRPolicever110`，磁盘上是 `NTR_Police_ver1_10`。

于是"进度"列对**几乎所有**游戏都是空的（这次三局显示的 0% 是昨天旧报告留下的残值）。
用户看到"没有进度/0%"，自然读作"这局没翻成功"。

### 修复

- `pipeline/index.js` 翻译结束后写出该文件（`entries / translated / pendingAtStart / requests / failures`）；
- `ui/MainForm.cs` 新增 `WorkStem()`，**逐字符照抄管线的 sanitize 规则**，并加一个前缀回退
  （`FindReportByPrefix`）以容忍规则将来变化；UiCheck 新增 4 项断言钉住这个推导。

## 七、这四局现在需要做什么

修复只改**管线代码**，游戏数据一行未动（验证时只在 deadbunny、release_0429 各新建了一个
`scenario_原版备份` 快照，属新增文件）。要让它们真正变成中文，**需要重跑一次**：

| 游戏 | 重跑后预计新增翻译量 | 说明 |
| --- | --- | --- |
| `deadbunny_1001` | **≈ 42,700 条** | 剧本首次可翻；量大，需要较长时间（可放进队列半夜跑） |
| `release_0429` | ≈ 21,000 条 | 同上 |
| `NTR Police` / `NTR Sisters` | ≈ 80 条术语 + 若干恒等重译 | 菜单类术语补翻 |
| `NTR Gyaru` | 几行 + 恒等重译 | 正文（message.txt）本已译；数据侧无正文 |

另外这四局正文仍有大量内容存放在**插件指令参数**（见 `docs/P11-MTool规则与译文导入.md` §5.3：
NTR Gyaru 12,114 条、deadbunny 4,246 条），需要"值侧 + 键感知 + 资源拒绝名单"的规则才能安全翻译，
本轮仍未做。
