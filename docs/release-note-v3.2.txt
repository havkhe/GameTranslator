# GameTranslator v3.2 —— 设置里就能验云端接口、整个目录可以随便搬、归档游戏不再"翻完没写回"

> **v3.2 是 v3.1 的修错版**：把 v3.1 里几处"看着成功其实没做事"的地方修好，
> 补上云端接口的自检工具，并让设置不再因为搬动安装目录而失效。
> 依然只有一个包（Vulkan 与 CUDA 12 两套后端都在里面）。

## 一、下载 / Downloads

- `GameTranslatorV3-v3.2.zip` —— **解压即用**：主程序 + 管线 + 工具 + 内置 node 与 ruby
  + **两套 llama.cpp 后端**（`llama\vulkan\` 与 `llama\cuda12\`），切换只改一个设置、离线即可。
- **模型 `.gguf` 默认就放安装目录**（默认「模型目录」= 安装目录本身）；放别处也行，
  在【设置…】里改「模型目录」指过去即可。
- 覆盖升级即可，**设置与密钥不会丢**：`ui-settings.ini`、`api-config.json`、`work\` 都不在包里。

## 二、v3.2 新增

- **【设置…】→「云端 API」里现在能直接测**（填完地址和 API Key 就能点，不必先保存）：
  - **「测试连通性」**：依次检查地址能不能解析 → 能不能读到模型列表、密钥过不过 →
    **真发一条翻译请求能不能拿到中文**；四类失败（密钥/额度、模型无权限、拒收思考开关、
    只思考不给译文）各自给出原因和处理办法，结果显示在下面那个框里。
  - **「检测可用模型」**：抓取模型目录（自动剔除向量/重排/视觉/语音/图像类），
    再逐个真发一条短请求，标出「可用 / 不翻 / 只思考 / 无权限 / 密钥 / 限流 / 超时」，
    **并把能用的模型按实测速度自动填进「模型链」**。这一步很值：实测某个密钥的 41 个文本模型里，
    23 个一调就 404——只看列表会挑到全都失败的模型。
  - 两个按钮跑的是包里的 `tools\api-check.js` 与 `tools\api-models.js`（命令行也能直接用），
    所以界面测到的就是管线真正会做的事。
- **整个安装目录可以随便搬**：设置里所有目录都能改（新增「工作目录」），而且
  **存在安装目录内的路径按相对路径保存**；某个路径指向不存在的位置时自动改回安装目录下的默认值，
  并在日志里写明。旧版本存的是绝对路径，一改名/挪盘就全部指回旧位置——表现就是"换台机器就不翻译"。
- **「模型目录」默认改为安装目录本身**（原来是写死的 `D:\galtrans`）。

## 三、修掉的问题

- **归档游戏"显示翻译成功、游戏却没变"**：重打包安全闸门拒绝写入时，管线**仍然以成功退出**，
  于是日志记成"第 N 次尝试成功"、队列继续往下走，而游戏一个字都没改。
  现在拒绝会**以失败退出（退出码 6）**，最后一行直接说明：
  "归档没有写回，游戏保持原样——这一局按失败计……译文都留在缓存里，重跑只会走「补丁+写回」，不会重翻"。
- **闸门的判据对 RGSSAD v3 过严**：原来比较"原样解包再打包"后的**整文件字节**。
  v3 的成员密钥随数据流递进，容器排版差 12 字节就会让 99.6% 的字节改变（实测），
  于是**本来安全的写入被拒绝**。现在改为**逐个成员比内容**（名字 + 该成员字节的 SHA-256，另比条目数），
  真正的损坏（成员字节变了、成员多/少）仍然抓得住，整文件差异只作为日志说明。
  实测那个 54 MB 的归档：旧版 `ok=false`（拒写），新版 `ok=true`，写回后游戏假名占比
  77.8% → 10.2%（已进游戏核对）。
- **云端慢模型被自己的看门狗掐断，却报成 `read ECONNRESET`**：客户端有个"45 秒没有任何字节就断开"的
  保护，那是为本地 llama-server 设计的（它一边算一边吐 token）。云端 `stream:false` 的推理模型
  **一个字都不发、最后一次性回包**，实测单次 32~215 秒，于是被自己断开、报成网络错误。
  现在**云端用 300 秒的窗口**（本地仍是 45 秒；`GT_STALL_MS` / `GT_API_STALL_MS` 可调），
  外层仍有管线自己的 10 分钟上限兜底。
- **关闭思考链的写法只有一种的假设**：以前只发 `enable_thinking`，被 400 拒收后就"让它思考"，
  而推理模型会把整个输出预算花在思考上、永远不给译文。现在**依次尝试三种写法**
  （`enable_thinking` → `chat_template_kwargs:{thinking:false}` → `reasoning_effort:"none"`），
  都不行才作罢；**只回思考不给译文时自动换链上下一个模型**，不再把整批记为失败。
- **CUDA 版在 GTX 10 系（Pascal）上被误判为不支持**：说明与程序提示都写着"10 系用不了 CUDA、会退回 CPU"，
  实测是错的——包内 CUDA 构建的内核含 `sm_50/61/70/75/80/90`，GTX 1060 上确实以 CUDA 运行。
  已全面更正（判定逻辑抽成两个可测函数），并附实测：**读入快 2~4 倍，但 4B 的 K 量化在 Pascal 上
  生成更慢，端到端仍是 Vulkan 更快**。

## 四、已知限制（如实写在文档里）

- **打包进单个 exe 的游戏（Enigma Virtual Box 这类）本工具读不到里面的 `www/data`**：
  需要先用第三方工具解包后再翻译。本工具不会内置该解包器，但会明确告诉你这一步。
- **归档游戏重跑会重翻一遍**：`unpack` 带缓存，重跑时不会重新解包原版归档，于是把上一次补丁后的
  **中文**当成待翻译文本再翻一遍（实测一次重跑的 4442 条"待翻译"里 4424 条是中文）。
  这一条**尚未修**：会浪费模型时间，也可能改动专有名词。翻译前请确认该游戏是否已完成。
- **VX / VX Ace 仍主要按字节判语言**：`.rvdata2` 里嵌着整份 Ruby 脚本，字节的拉丁比例不能说明语言，
  这类英文版可能仍被当作中文。
- **云端服务商有内容审核**：部分服务商会拦截成人向文本（实测某服务商约 4%）。
- **两个后端的 llama.cpp 版本不同**：包内 `llama\vulkan\` 是 build 10298、`llama\cuda12\` 是
  build 11571。对比两套时其实在比版本，介意的话可自行用 `download-llama.ps1` 把两边换成同一版。

## 五、安装 / 更新

1. 解压覆盖到旧目录（或新目录）即可；**设置与密钥不在包里**，升级不会覆盖它们。
2. 双击 `GameTranslatorV3.exe`：首次使用在【设置…】里填「模型目录」与「扫描路径」。
3. 主程序与界面源码随包提供（`ui\`），改了界面用 `build-ui.bat` 重新编译，再用根目录的
   `应用新版本.bat` 应用（它在程序运行时拒绝替换，避免打断正在跑的翻译）。
