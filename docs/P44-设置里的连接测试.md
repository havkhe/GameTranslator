## 一、加了什么（都在【设置…】→ 云端 API 那一段，紧挨着「模型链」）

| 控件 | 作用 |
|---|---|
| **测试连通性** | 依次查：地址能不能解析 → 能不能读到模型列表、密钥过不过 → **真发一条翻译请求**能不能拿到中文。把上面四类失败各自的原因和处理办法写在结果框里（401/403 密钥·额度、404 模型无权限、400 拒收思考开关、只思考不给译文、返回了但没中文） |
| **检测可用模型** | 抓模型目录（按程序内置规则剔除向量/重排/视觉/语音/图像类），然后**逐个真发一条短请求**（每个最多 30 秒，只测前 15 个），标出「可用 / 不翻 / 只思考 / 无权限 / 密钥 / 限流 / 超时」，**并把能用的模型按实测速度自动填进上面的「模型链」** |
| **停止** | 运行中可以随时掐掉 |
| 结果框 | 只读多行、等宽字体，工具的每一行输出**实时**滚动显示 |

用当前对话框里的值跑，**不必先保存**（填完 Key 直接点就行）。密钥进子进程的**环境变量**
（`GT_API_KEY`），既不进命令行也不落盘；关对话框会顺手结束还在跑的那个进程。

## 二、为什么按钮只是"转发"给工具，而不是在 C# 里重写一遍

两个按钮只决定**运行哪个工具**；检查逻辑本身仍然只在 `tools/api-check.js` 与 `tools/api-models.js` 里，
和命令行走的是同一份文件。窗口里再抄一份"稍微不一样"的请求逻辑，是"测试按钮证明了别的东西"这类
事故的标准成因（这套代码已经因为"两处实现不一致"栽过一次）。

工具为此加了两行机器可读输出，窗口靠它们行动（措辞随便改都不影响）：

```
CHECK=ok | CHECK=fail          ← 结论行
CHAIN=<逗号分隔的模型名>        ← 检测可用模型跑完，窗口据此填「模型链」
```

**顺手做的一处加固**：地址在交给命令行之前先过 `Uri` 正规化（只接受 http/https）。
既把"忘了写 https://"这种常见笔误变成一句明确的提示，也保证递给子进程的是**解析器产出的字符串**，
打字时混进来的引号/空格/控制字符活不下来。（.NET Framework 没有 `ProcessStartInfo.ArgumentList`，
按本项目 `build-ui.bat` 里记下的原因，参数只能手工拼接——所以拼之前先把输入夹住。）
