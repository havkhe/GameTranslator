# P17 —— 暂停：从"两局之间"改为"两条请求之间"

对象：`pipeline/translate/index.js`、`pipeline/index.js`、`ui/MainForm.cs`、`ui/UiCheck.cs`、
`tools/unit-pause.js`。承接 `docs/P16-模型状态与实际加载.md`。

起因：用户报告"暂停功能似乎失效"。

---

## 一、为什么看起来失效（不是代码坏了，是粒度）

暂停的实现在两个运行循环里都有，但都只在**两个游戏之间**检查：

```csharp
while (_paused && !_cts.IsCancellationRequested) await Task.Delay(500);   // 在"开始下一局"之前
```

所以点「暂停」只意味着"当前这一局跑完就不再开下一局"。按钮本身是有反应的（`暂停` 变灰、`继续` 变亮、
日志一行），但**翻译继续** —— 而在跑的那一局是 `金色complex 剣鬼バルゴ`（extract 2.2 MB），
这一局本身就要跑很久（本会话记录过一局 58 分钟），期间屏幕毫无变化，于是就是"失效"。

## 二、改法：协作式暂停，粒度降到一条请求

管线是独立进程，所以暂停必须是**协作式**的：

1. 窗口点「暂停」→ 写出 `work\paused.flag`；点「继续」→ 删除它；
2. `pipeline/index.js` 把该路径交给 translate（与其它工作文件同一个目录，无需新增命令行参数）；
3. `pipeline/translate/index.js` 的**每组请求之前**调用 `waitWhilePaused(flag)`：
   文件存在就每 500 ms 轮询等待，开始等待时打印一行 `PAUSED …`，恢复时打印 `RESUMED`。

于是延迟 = **一条请求的时间**（几秒），而不是一局的时间；因为什么都没拆掉，继续时正好从停下的那条接上。

```
实测（tools/unit-pause.js）：标记存在期间 24 条待译、3 组请求，**发出的请求数 = 0**；
删掉标记后立刻跑完，24 条全部入缓存。
```

## 三、配套的三处细节

| 项 | 处理 |
| --- | --- |
| **遗留标记** | 程序在暂停中被关掉，会留下 `paused.flag`；下一次运行开始时 `ResetProgress()` 会清除它（并写一行日志），否则新一轮会一直等一个没人按的「继续」。点「终止」时也一并清除。 |
| **进度面板显示"已暂停"** | 1 秒一次的定时器里，`_paused` 为真就把「速度」行改写为 `速度：已暂停（当前请求结束后不再发出新请求）`。这是"按钮起作用了"在长局里的唯一可见证据。 |
| **检查翻译时禁用暂停/继续** | `StartCheck` 是**同步**跑在 UI 线程上的（`p.WaitForExit`），此时窗口不处理消息，按钮即使可点也不会响应 —— 现在它们在那段时间置灰（`_checking`）。 |

暂停按钮的 tooltip 也改成如实描述：**「暂停翻译：当前这一条请求结束后不再发出新请求（通常几秒内生效），进度与缓存都保留。「继续」从停下的地方接着跑。要彻底停下用『终止』。」**

`_uicheck` 新增 6 项：标记文件名必须叫 `paused.flag`、点「暂停」文件出现、点「继续」文件消失、
运行开始时清除遗留标记，**以及"部署里的管线确实读了同一个 `paused.flag`、确实有 `waitWhilePaused`"** ——
后两项在同步管线之前真的报了失败，正好证明它能抓出"界面与管线版本不一致"。
