# GameTranslator v3.3.1 —— 英文版游戏的对白现在会被翻译

> **v3.3.1 是 v3.3 的修复版**：只动"英文版游戏"这条链路，日文工具链不受影响。
> 依然只有一个包（Vulkan 与 CUDA 12 两套后端都在里面），覆盖升级即可。

## 一、下载 / Downloads

- `GameTranslatorV3-v3.3.1.zip` —— **解压即用**：主程序 + 管线 + 工具 + 内置 node 与 ruby
  + **两套 llama.cpp 后端**（`llama\vulkan\` 与 `llama\cuda12\`），切换只改一个设置、离线即可。
- 覆盖升级即可，**设置与密钥不会丢**，已翻好的记录也不会被动。

## 二、修了什么：三处叠在一起，让英文版游戏"翻了等于没翻"

实测对象是一个 15,366 行对白的英文版 VX Ace 游戏。**修前对白中文占比 0%（抽取只拿到 190 条，对白一条没进范围），修后 94.8%（14,572 行）。**

### 1. 抽取器只认日文，英文对白在进入翻译之前就被扔掉了

VX Ace 的抽取器要求字符串里含假名或汉字，于是**纯英文对白全部被丢弃**：
`VX_RAW 1375 FILTERED 0` —— 连 JS 侧的规则都没机会看到它们，而 JS 侧早就有完整的英文判定
（"至少两个词或句末标点，排除标识符/文件名"）。现在抽取器只做粗筛（日文或任意拉丁字母），由 JS 规则判定。

### 2. 补丁和缓存对"空白"的理解不一致，已翻好的译文写不进去

JS 的 `\s` 把全角空格 `U+3000` 当空白，Ruby 的 `\s` 不认。而日英游戏的台词常以 `　` 缩进——
缓存键是 `So this is…`、数据里是 `　So this is…`，**2,810 条已有中文译文的条目被报成"数据里没有"**，
一直留在英文。两边现在按同一规则归一（含 `U+3000`/`U+00A0`）。

### 3. 英文侧的三条规则是按日文标定的，误杀了正确译文

- **长度下限**"译文不得短于原文 25%"：日→中合理，英→中本来就该缩短 4-5 倍。
  `Guaranteed high pay!` → `报酬丰厚！`、`Women should refrain from stepping outside town.` → `女性应避免外出小镇。`
  都被判"太短"。**英文源的下限改为 10%**，日文源仍是 25%。
- **"反斜杠 = 路径"**：RPG Maker 的控制符全以反斜杠开头（`\C[27]`、`\!`、`\N[1]`），
  于是带颜色符或换行转义的英文台词全被当成路径拒掉。现在先剥掉控制符，再判断是否真的像路径。
- **"单个词多半是 id，不翻"**：但事件消息行（`@text`）一行就是一句台词，
  `Sister` / `Storekeeper` / `Soldier` 是**说话人名**，这类有 3,907 行、此前一直留在英文。
  新增 `isTranslatableMessage()`，只对消息行放宽。

## 三、验证

- 单元测试：**21 个文件、517 项断言全部通过**（新增 13 项专盯这三条英文规则：控制符不算路径、
  消息行的单词要翻、`EV001` 仍算 id、英文源 10% 下限、日文源仍 25%）。
- 端到端：两个真实英文版游戏（一个 15,366 行的 VX Ace、一个 23,000+ 行的 MV）实测，
  对白从 0% 到 94.8%；剩余部分主要是专有名词（`Aisha`、`Viviana`）和格式怪异行。

## 四、两条使用提示

- **免费公共接口不要同时跑两个任务**。实测：两个翻译任务同时以 8 并发打同一个接口，
  单次运行出现 10,461 条 `request-failed`——接口扛不住。串行跑，或并发设 4。
- **并发批次数**建议 4-8（只对云端有意义，本地模型服务是单并发）。

## 五、如果你的库里还有英文版游戏

这批修复对**所有英文版游戏**生效（VX Ace 与 MV/MZ 都受益于第 3 条）。
之前跑过但没有对白的英文版游戏，**直接重跑即可**——缓存会复用已有的译文，只补缺的部分。
