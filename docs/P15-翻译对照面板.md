# P15 —— 翻译对照面板（实时显示原文 / 译文）

对象：`pipeline/translate/index.js`、`pipeline/index.js`、`ui/MainForm.cs`、`ui/UiCheck.cs`、
`tools/unit-translate-pairs.js`。承接 `docs/P14-插件参数覆盖.md`。

## 一、要什么

翻译时能同时看到"这一条翻之前是什么"和"翻之后是什么"，用来随手核对质量。

## 二、怎么传

管线每译出一条**新**译文，就打印一行让窗口读取：

```
PAIR {"src":"「おはよう、先生」","dst":"「早上好，老师」"}
```

- 由 `translate()` 新增的 `onPair(src, dst)` 回调触发，`pipeline/index.js` 负责行格式（与 `PROGRESS`
  同样的分工：调用方拥有线格式）；
- 用 `JSON.stringify` 转义，所以**一对永远是一行** —— 原文里的引号、换行都不会把行拆开（测试钉住）；
- 窗口的 `OnPipelineLine` 识别 `PAIR ` 前缀后**直接路由到对照面板，不写入日志**（否则日志会被刷掉）。

### 只报"本次新产生的"

命中缓存的条目不报。全部命中缓存的一轮**什么都不显示** —— 这是如实信号：本次没有新翻译。
测试专门钉住这条（第二次运行 0 对、0 请求），因为另一种做法（把缓存里的对照回放出来）会显示
一大堆本次根本没翻的内容。

## 三、怎么显示（右侧面板新增「翻译对照（实时）」）

```
GroupBox 翻译对照（实时）  (Dock.Top, 200)
 ├ pairTop  (TableLayoutPanel 2×2)   原文 [pairSrc]  译文 [pairDst]   ← 当前这一对，只读、可多行
 ├ _pairList (ListView 原文|译文)     最近 200 条，最新在**最上面**，列宽随面板
 └ pairBar  (FlowLayoutPanel)        [✓] 自动滚动   [清空对照]   本次已显示 N 条
```

- 两个框用多行只读 TextBox 而不是列表列：一句话在列里会被截断；
- 列表单元格把换行折成空格（列表一行装不下多行），完整原文/译文放在行 tooltip 里；
- `自动滚动` 默认勾选，始终停在最新一条；关掉后可以安心往回翻；
- 每次**运行开始**（`ResetProgress`）清空，所以面板描述的永远是当前这一轮；
- 纯内存，不落盘；候选颜色上原文灰底、译文浅绿底，一眼分得清哪边是成品。

## 四、验证

**端到端（真管线 + 本地假模型）**：`node pipeline/index.js <小测试游戏> <工作目录> 18999 translate`
→ 5 个条目产出 5 行 PAIR，其中包含插件参数的值 `ヒロカ`，而**资源文件名
`オープニング_3行で_01` 一行都没有**（P14 的拒绝名单生效）。

```
PAIR {"src":"ミア","dst":"文文"}
PAIR {"src":"「おはよう、先生」","dst":"「文文文文、先生」"}
PAIR {"src":"ヒロカ","dst":"文文文"}                     ← 插件参数的值
PATCHED 5 MISSING 3 FILES 1
DONE
```

**单元测试** `tools/unit-translate-pairs.js`（12 项，进程内起 http 假模型，不用子进程）：
每条约新译文都报告、插件参数的值在其中、第二次运行 0 对 0 请求、**显示层回调抛异常也不影响翻译**、
线格式含引号/换行时仍是一行。

**界面自检** `_uicheck.exe` 104 项全绿，新增：两个只读多行对照框、历史列表、自动滚动开关、
计数标签，以及**用真实线格式喂 `OnPipelineLine`** 验证解析与刷新（含"最新的排最前""清空回初始"
"PAIR 不进日志"）。

顺带修掉一个自检缺陷：队列那几条断言原本假设"队列是空的"，用户一旦真的用队列就会误报 5 条失败。
现在改成断言**不变量**（"开始队列"的可用性 == 队列非空；新建组后组数 +1；新组节点编号与成员数），
与用户的 `work\queue.json` 实际内容无关。

## 七、注意

- 面板只在当前窗口会话内累积，最多 200 条；关程序即清空（它只是参考，不是记录）。
- 译文框显示的是**模型产出的原文**（含装饰符号还原后的形态），与最终写回游戏的值一致。
