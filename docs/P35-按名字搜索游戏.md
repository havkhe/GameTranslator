## 一、加了什么

游戏列表上方、工具栏下方多了一行：

```
搜索游戏名： [__________________________]        显示 12 / 139   [清除]
```

- **边打边筛**（`TextChanged`），不区分大小写；
- **空格分隔多个词，要求全部命中**：`ntr sisters` 只留下同时含 "ntr" 与 "sisters" 的名字；
  `ntr police` 不会命中 `NTR Gyaru`。分隔符同时认半角空格、Tab 与**全角空格**（从日文发行名里粘过来的词不会带上隐形分隔符）；
- `Esc` 或「清除」清空；
- 右侧灰字显示 `显示 12 / 139`（只在有筛选时出现）。

## 二、一条明确的边界：**筛选只改显示，不改"跑什么"**

列表是虚拟模式（`VirtualMode`），行是按需生成的，所以这里引入了一个"视图"列表：

```csharp
private readonly List<GameItem> _view = new List<GameItem>();   // 当前显示出来的那些
```

- `RetrieveVirtualItem`、`ToggleRow`、`ToggleRows`、`CurrentGame()`（右键菜单用）全部改成走 `_view`；
  行号是**显示位置**，不是模型位置 —— 否则筛选之后点一行会勾错游戏（这种错最难发现）。
- **真正要跑的还是"所有已勾选的游戏"**，与筛选无关。这是有意的：如果一个游戏在筛选之前就被勾上了，
  打字搜索不应该把它悄悄踢出批次。底下计数行一直写「共 139 个游戏，已勾选 N 个」，
  有筛选时再补一句「（筛选显示 12 个）」—— 两个数字都在，谁都不会被藏起来。
- **「全选 / 取消全选」作用于显示出来的那些**（有筛选时这是唯一合理的读法），tooltip 里写明了。
- 列表在翻译进行中也照样可以筛选（`_list.Enabled` 一直是 true，筛选不动任何数据）。

## 三、匹配规则（单独一个静态方法，可测）

```csharp
private static bool MatchesQuery(string name, string query)
{
    var q = (query ?? "").Trim();
    if (q.Length == 0) return true;                       // 空查询 = 全部
    foreach (var term in q.Split(new[] { ' ', '\t', '\u3000' }, StringSplitOptions.RemoveEmptyEntries))
        if (name.IndexOf(term, StringComparison.OrdinalIgnoreCase) < 0) return false;
    return true;                                          // 每个词都必须命中
}
```

只匹配**游戏名**（列表第一列显示的那个），不匹配路径 —— 按你说的"搜索游戏名字"来。
