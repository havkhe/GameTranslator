# P10 —— 文本文件覆盖：`text/*.txt`、资源名误译与覆盖率统计

对象：仓库 `pipeline/`、`tools/`，部署 `D:\GameTranslatorV3`。
承接 `docs/P9-启动与游戏状态.md`。起因是两条用户报告：

- `NTR Gyaru` 未汉化却显示（接近）已汉化，是否"有大量未汉化文本在其他文件中"；
- `(同人ゲーム)[2021-06-26][RJ333113][金色complex] 慰安騎士フラウ` 同类问题；
- 提示：需要翻译的文件可以参考 MTool 的 `TrsData.bin`。

---

## 一、结论先说

**是，有。** 有两条不同的原因，都在 `data/*.json` 之外：

| 位置 | 是什么 | 本回合的处理 |
| --- | --- | --- |
| `text/*.txt`（Text2Frame 插件） | 整个正文脚本，按行播放 | **已支持**：新增提取/回填模块 |
| 插件指令参数（事件码 357 / 657） | `键 = 值` 形式的插件参数，混着正文与图片名 | 仍不支持，见第四节 |
| `bgm.name` 等音频文件名字段 | 被当成文本翻译，游戏加载不到音频 | **已修复**（上一提交 f95c32a3） |

## 二、`text/*.txt`：正文根本不在 data 里

Text2Frame 插件把消息文本放在数据目录旁边的 `text/message.txt`，事件里只有一个标签。
于是提取器只看得到很少的字符串：

```
NTR Gyaru   data 里可译字段 17 条；text/message.txt 另有 99 行，其中 67 行是日文
牧场Ver1.1   data 里已无正文；text/*.txt 196 行，其中 102 行是日文
```

实测 `NTR Gyaru`：data 的 17 条**全部**已译，而 `text/message.txt` 的 67 行**一行未译** ——
所以界面按 data 算会当成译完了，进游戏却全是日文。

### 新增 `pipeline/extract/text2frame.js`

- `textRoots(game)`：同时认 `text/`（数据目录旁边）与 `www/text/`（MZ 的 web 根）两种布局；
- `extract()`：逐行取，行号就是位置（`file = "text/message.txt"`，`path = "$[3]"`）；
  空白行不入队，说话人行（`　夢前和漢：`）按文本处理；
- `patch()`：**逐行回填，行数严格不变** —— 插件按行号播放，行数一变，之后每条消息都错位；
  CRLF 也原样保留；
- `ensureBackup()`：写之前先做 `text_原版备份`，与 `data_原版备份` 同一个约定，
  否则第二遍会把中文再送进模型；
- 提取时若发现该行已是中文则跳过（`isChineseLike`），所以重复运行安全。

管线接线（`pipeline/index.js`）：提取阶段合并 `TEXT2FRAME` 条目，回填阶段输出
`PATCHED_TEXT2FRAME`，与既有的 `RESOURCES` / `PATCHED_RESOURCES` 并列。

单元测试 `tools/unit-text2frame.js`（30 项）钉住最要紧的性质：**行数不变**、空行仍为空、
CRLF 保留、两种目录布局、pristine 快照只建一次、第二遍不重复入队。

## 三、覆盖率统计为什么之前是错的

两处测量错误，都会让"已汉化"判断失真：

### 3.1 `translatedCount` 用字段名当判据

旧实现把任何 `...parameters[N]` 都算成"文本字段"，不看事件码。实测 `NTR Gyaru`：
含假名的 event 参数字段共 13614 个，其中**只有 50 个**是提取器真正会翻的（code 401 slot 0），
其余 13564 个是：

```
 8806  code 657 slot 0   插件指令参数（"質問メッセージ = "、"ウィンドウ画像 = " …）
 3308  code 357 slot 2   插件指令参数（选择肢文字、图片名 …）
 1330  code 231 slot 1   显示图片的**图片文件名**（"おっぱい"）
   92  code 119 slot 0   跳转标签
   20  code 118 slot 0   标签
    8  code 108 slot 0   注释
```

分母被这些撑大，百分比被压得极低（`さくらエグゼック` 显示 93 %，实际 100 %）。

**改法**：两侧都由提取器自己产出，范围不可能漂移；按"唯一原文"计数 ——
原文串还在 live 里原样出现即未译，不在即已译（与缓存以原文为键一致）。

### 3.2 状态不看 `text/*.txt`

`tools/game-state.js` 增加 `text2frameCounts()`，并把正文覆盖率**并入**判定：
数据全译但正文未译时，状态不能是"已汉化"。`tools/audit-lib.js` 的对话统计同样计入
`text/*.txt`（否则会把 67 行日文正文报成"files 0 / total 0"）。

### 重扫结果（119 个游戏）

| 状态 | 修前 | 修后 |
| --- | --- | --- |
| 已汉化（本项目） | 4 | **11** |
| 已是中文 | 3 | 3 |
| 部分汉化 | 11 | **5** |
| 未汉化（已还原） | 45 | 44 |
| 未汉化 | 15 | 15 |
| 打包归档 / VX Ace / VX | 21 / 12 / 8 | 21 / 12 / 8 |

`NTR Gyaru` → **部分汉化 已译 17 串（text/*.txt 还有 67 行日文，共 99 行）**。

## 四、仍然不支持的：插件指令参数

正文还有很大一块在**插件指令**里，形如 `键 = 值`：

```
code 657  "質問メッセージ = "            值才是文本
          "選択肢リスト = [{label: ...}]"  列表里的 label 是文本
          "ウィンドウ画像 = "              值是**资源文件名**
code 357  ["LL_GalgeChoiceWindow","showChoice","選択肢の表示", …]   第 3 项是提示文本
```

这里文本与资源名、脚本混在同一个字符串里，整串翻译一定会像 `bgm.name` 那样弄坏资源。
要做就得**按 `键 = 值` 解析、对资源类键（`画像`／`音声`／`ファイル`…）设拒绝名单**，
并先在一两个游戏上验证。本轮没有做，因为它属于有破坏风险的范围变更，需要单独决策。

## 五、`TrsData.bin` 没能当作基准用

用户建议以 MTool 的 `TrsData.bin` 为准列出"需要翻译的文件"。实测不可直接用：

- `NTR Gyaru\TrsData.bin` 4,726,453 字节；字节直方图接近均匀（ASCII 可打印 37.1 %，
  与 95/256 一致），无 gzip/zlib/brotli 头 —— **加密或强压缩**，非明文；
- 依据公开资料，`TrsData.bin` 是 MTool 保存译文的 JSON 键值对，但带文件属主校验，
  只能由 `ManualTransFile.json`（**未译**原文导出）间接用；
- 库内确实存在明文副本：`PrisonBrave_1.1.0\ManualTransFile.json`（32,783 条），
  `MTool_MapDataCache\*.json`（MTool 自己解析过的数据副本）。实测 `ManualTransFile.json`
  的键就是**原文串**（不是文件路径），并包含 `const text = "` 这类脚本片段，
  说明 MTool 的抽取范围比本项目宽（含脚本）。

结论：`TrsData.bin` 不能作为"文件清单"基准；替代基准是用 `data_原版备份` 与新模块
直接扫描游戏本身（本回合即如此），它给出的正是"哪些文件、哪些行还没翻"。

## 六、资源名误译的全库复查

上一提交修的是提取/回填会翻 `bgm.name` 的缺陷。本回合对全库复查同源性损坏：

```
受损游戏 1 个，字段 3 个（NTR Gyaru 已在上一步修完）
  (同人ゲーム)[へんたぃロリッ♪くらぶ] 無垢な見習い冒険者とゴブリン達。+姫もいるよ♪
    Map017.json  .bgm.name:      "●城镇　oshironobutoukai"  → "●町　oshironobutoukai"
    Map019.json  .bgm.name:      "●城镇　oshironobutoukai"  → "●町　oshironobutoukai"
    System.json  .titleBgm.name: "●标题　nagagutsudeodekake" → "●タイトル　nagagutsudeodekake"
```

已按 `data_原版备份` 还原，并写出 `data_资源名修复前快照`。该游戏是 MTool 汉化的
（目录里有 `一键恢复汉化.bat`、`与工具一同启动.bat`、`TrsData.bin`），
即这两处不是本管线的输出，但还原后游戏能正常加载资源。
