## 一、「不是 RPG Maker 却被扫出来」——其实是**归档游戏没被认出引擎**

`DetectEngine` 只找**散装**的 `data` / `www\data` 目录。而 VX / VX Ace 游戏通常把整个数据树封在
`Game.rgss2a` / `Game.rgss3a` 里，**根本没有 data 目录** → 引擎列显示 `?`，看起来就像"不是 RPG Maker"。

实测（复刻窗口的扫描规则跑 `J:\game`，深度 4）：**找到 100 个目录，其中 25 个引擎是 `?`**，
而它们全都被管线自己判成归档游戏：

```
  深度3  UI=?   pipeline=VXAce(归档)     Bitch Dancer's Quest
  深度3  UI=?   pipeline=VX(归档)        [151231][アンコクマリモカン] SNEAK IN DESPERADA ～殺し屋少女・敗北陵○RPG Ver.1.03
  深度3  UI=?   pipeline=VXAce(归档)     [RPG] [オニチク屋!] オニチクエスト ～処女(ゼロ)から始まる孕まされ性活～
  …
```

### 你点名的那个游戏

```
[151231][アンコクマリモカン] SNEAK IN DESPERADA …Ver.1.03
  Game.exe  Game.rgss2a  Save1.rvdata  savec.rvdata  TrsData.bin …
```

`Game.rgss2a` **就是 RPG Maker VX**（不是 VX Ace：`.rvdata` 存档也是 VX 的），而数据全在归档里、
没有 `data` 目录 → 所以旧代码显示不出引擎。

**改法**：`DetectEngine` 现在是

1. 散装数据目录 → `.rvdata2` = VX Ace、`.rvdata` = VX、`.json` = MV 或 MZ（按 `rmmz_core.js` / `rpg_core.js` 区分）；
2. 否则看三个归档名，**读归档头的前 8 字节**：`RGSSAD` 魔数 + 版本号 —— **版本 1 = VX，版本 3 = VX Ace**
   （与 `pipeline/archive/rgssad.js` 的 `archiveVersion()` 同一判据）；
3. 都没有 → `?`（不猜）。

引擎名也统一成**管线自己的叫法**（MV / MZ / VX / VX Ace），不再混用旧缓存里的 `MV/MZ`。

## 二、「大量无关或重复的扫描目录」——游戏内部不再登记成新游戏

旧的遍历是"见到就收、然后继续往里走"，于是**一个游戏内部的启动目录也被当成独立游戏**。
从你的列表里就能看到这些（都是同一次扫描留下的）：

```
ストアマトロンNTR\RJ01121436\Game
ストアマトロンNTR\RJ01121436\３Ｋ～完全管理姦淫\Game        ← 同一个游戏里的两处
(同人ゲーム)…長谷川麻衣のメイド飼育調教\Game（セリフ有り）
(同人ゲーム)…長谷川麻衣のメイド飼育調教\Game（セリフ無し）  ← 同一游戏的两个版本
prisonbrave_1.1.0\Tool
びたみんクエスト 2ND ATTRACT\びたみんクエスト 2ND ATTRACT    ← 发布目录与游戏目录同名，同一个游戏被登记两次
```

正如你说的：**找到第一个 game.exe 之后，里面的东西就是那个游戏自己的子程序**。

**新规则**（`ScanPath`）：

- 一个目录被判定为游戏 → 收下它，**它的子目录不再当新游戏**（不再往下登记）；
- **例外：附赠游戏**。名字像 `bonus / おまけ / オマケ / 特典 / omake / extras / 外伝 / 外传 / gaiden / 追加 / another`
  的子目录**继续走**，它是独立的小游戏，值得翻译（实测 `无知少女的乡村韵事\…\Yutaka Gaiden外传`）；
- 游戏内部其它"启动目录"**不静默丢弃**，而是记进日志：
  `游戏内部还有 N 个启动目录，未当成新游戏（多为该游戏自己的子程序）：A、B、C…。若其中有你要翻译的独立游戏，用「添加游戏」直接指向它即可。`

`重新扫描全部` 只**合并**、从不删除，所以你列表里已有的那些条目（包括早先扫进来的附赠游戏）不会被弄丢。

### 扫描深度：默认 4 → 6

深度 4 会让"发布目录里再套一层"的游戏漏掉 —— 实测你列表里 **110 个游戏中有 36 个比深度 4 更深**
（`更多game\Human Farm -Practice Section-\Human Farm -Practice Section-`、
`更多game\Loretta's Brand New Job\Loretta's Brand New Job`、`Lizbel ver.1.14+DLC\Lizbel ver.1.14+DLC` …）。

因为新规则**遇到游戏就停下**，深度只看"发布包装有几层"，代价小了很多，所以默认值改为 **6**。
你现有的 `ui-settings.ini` 里是 4 —— **请在【设置…】→ 扫描深度 里改成 6（或 8）**再重新扫描。

## 三、验证

UiCheck 192 → **214 项**，全部通过（部署目录用部署自身源码构建后运行）：

- **引擎**：散装 `.rvdata2` → VX Ace、散装 `.rvdata` → VX、`json + rpg_core.js` → MV、`json + rmmz_core.js` → MZ、
  **合成归档头**（`RGSSAD` + 版本 1）→ VX、（版本 3）→ VX Ace、空目录 → `?`；
- **附赠目录**：`bonus / Bonus Game / おまけ / 特典 / Yutaka Gaiden外传 / extras` 被识别，
  `Tool / game1 / game2 / Game（セリフ有り）/ js / plugins / data` 不被识别；
- **默认深度**：新建配置 ≥ 5（你 ini 里的值由你自己定，不作断言）。

## 四、部署

`GameTranslatorV3.exe.new` 已暂存（界面改动，需要换 exe）。
**等当前翻译任务跑完 → 关掉程序 → 双击 `应用新版本.bat`**，
然后【设置…】把扫描深度改成 6 → 重新扫描全部。
