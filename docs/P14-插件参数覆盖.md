# P14 —— 插件指令参数覆盖（值侧 + 键感知 + 资源拒绝名单）

对象：`pipeline/extract/rules.js`、`extract/mv.js`、`patch/mv.js`、`tools/unit-plugin-args.js`。
承接 `docs/P13-四局失败成因与修复.md` 第七节留下的"覆盖缺口"。

---

## 一、为什么之前不动它

插件指令（事件码 356 / 357 / 657）的参数是 `键 = 值` 形式的行，**键名是插件自己的日文参数名**：

```
対象キャラ名 = 琵琶乃          キャンセル許可 = false        ウィンドウ画像 =
結果受け取り変数 = 15          ウィンドウ幅 = 720            リソースラベル = Hiroka_Prologue_000
ファイル名 = オープニング_3行で_01                          取り込み元ファイル名 = message.txt
```

实测一局（凍堂ヒロカ）这类含假名参数有 **222,562 条**，其中键名是日文的约 172,596 条、
值是文件/资源名的 10,448 条。**整串翻译会同时翻坏键名与资源名** —— 与已在 P10 修过的
`bgm.name`（44 处）、`sounds[].name`（5 处）、脸图名（13 处）同类，但量大百倍；而且隐蔽
（路径形如 `parameters[0]`，审计的资源判据看不出是资源）。MTool 的键表恰是"整串当文本"，
这就是本分支一直拒绝照它对表的原因。

## 二、这次的做法

**只取值，且只取"真的是文本"的值**，四道过滤（每一条都来自实测，不是猜）：

| 过滤 | 依据 |
| --- | --- |
| **值必须含假名** | 插件参数里无假名的值是名字/id/汉字词，中文里字形不变：`対象キャラ名 = 琵琶乃`（人名）、`リソースラベル = …`（id）。这一条去掉了 moralist 约 6 万条空操作与 NTR Gyaru 全部 7,596 条英文值 |
| **键排除资源类**（`リソース｜ファイル｜フォルダ｜画像｜素材｜パス｜音声｜ボイス｜サウンド｜スクリーン｜アイコン｜アニメ｜モーション｜タイル｜グラフィック｜立ち絵｜bgm｜bgs｜voice｜sound｜image｜img｜file｜path｜folder｜sprite｜picture`） | `ファイル名 = オープニング_3行で_01` **含假名**，只能靠键拦下 |
| **值排除数字/布尔/JSON 结构** | `= 15`、`= false`、`選択肢リスト = [{...}]`（JSON 里的文本在结构内部，重建会破坏插件数据） |
| **值排除文件/路径/URL** | 漏过键判据的裸引用 |

回填时**只用值替换值**，键、等号（含全角 `＝`）与作者的空格**逐字节保留**；且回填走**同一套判据**，
所以"提取不会入队的值"即使缓存里有译文也**绝不会**被写入 —— 这是资源名不会被翻坏的机制保证。

## 三、实测影响（先量后改）

| 游戏 | 拟新增条目（去重） | 被规则挡下 |
| --- | --- | --- |
| `NTR Gyaru` | **0** | 7,596 |
| `deadbunny_1001` | **64** | 5,012 |
| `凍堂ヒロカ 隷雄譚` | **5,322** | 123,692 |
| `NTR Police ver1.10` | 0 | 0 |
| `(同人ゲーム)[静かな北国]` | 0 | 0 |
| `NTR Sisters` | 0 | 0 |

改后实跑提取：

```
deadbunny   44,865 → 44,920  (+55，去重后，其余与既有字段重复)
moralist           → 10,763  (+5,322)
```

新增值的样例（确实是玩家可见文本）：

```
キャラ名 = ヒロカ              プリセットの登録名 = 怒り(発情)          text = レンの調教
```

被拒绝的样例（保住了）：

```
ファイル名 = オープニング_3行で_01  ← 剧本文件名
リソースラベル = Hiroka_Prologue_000 ← 对白资源标签
対象キャラ名 = 琵琶乃               ← 人名，中文里不变（且新加的 identity 门禁也会拒收恒等译文）
キャンセル許可 = false / 結果受け取り変数 = 15
選択肢リスト = [{"label":"Still sleeping"}]  ← JSON 结构
```

**注意 `NTR Gyaru` 是 0**：它的选择支文字是英文、正文在 `text/message.txt`（早已译完），
所以这条规则对它"无收益也无风险"—— 也说明它此前显示的"0% 中文化"是**度量假象**，不是漏翻。

## 四、仍未覆盖的（有意，据实测）

| 位置 | 为什么不碰 |
| --- | --- |
| 指令对象上的 `comment` / `text` 字段 | 插件自定义存储，语义不明；在受测的这几局里计数为 0 |
| `code 357` slot 2（指令显示名，如 `文章の表示`） | **只影响编辑器**，玩家看不到 |
| `code 357` slot 0（插件名） | ASCII |
| `code 108 / 408`（注释） | 编辑器备注，实测为 `注釈テスト`、`表情差分:悔しい` |
| `code 118 / 119`（跳转标签） | 翻了会破坏跳转（NTR Police 未覆盖的 116 条全是这类） |
