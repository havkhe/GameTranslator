## 1. 3.4.1 提示词残留

### 定位

报告只看到 1 处（watchdog 的字符串扫描），实际 **6 处**，因为旧扫描器有两处盲区：
只统计"对象属性"上的字符串（`parameters[0]`、`terms.commands[i]` 这类**数组直接元素**全被漏掉），
且不检查 `resources/<locale>/`。

| 位置 | 污染值 | 原始值 |
|---|---|---|
| `data/Tilesets.json` `[6].name` | `每行输出一条译文，不要编号、不要JSON、` | `チェストウッド` |
| `data/resources/ja-JP/SystemText.json` `SYSTEM_MENU_LOAD` | 同上 | `ロード` |
| `data/resources/ja-JP/SystemText.json` `HEADER_TITLE_ADV_CHESTWOOD` | 同上 | `チェストウッド` |
| `data/resources/ja-JP/Stuff.json` `STUFF_MIZOHONE` | 同上 | `みぞほね` |
| `data/resources/ja-JP/Hiroka_Prologue.json` `Hiroka_Prologue_076` | `…………每行输出一条译文…♥` | `…………っ♥` |
| `data/resources/ja-JP/Hiroka_HEV2.json` `Hiroka_HEV2_456` | `每行输出…♪♥` | `ァ゜――……♪♥` |

`SYSTEM_MENU_LOAD` 是**读档菜单项**——玩家直接看到。

### 根因

`batcher.parseResult` 会剥掉答复里的提示词行，但它**故意至少保留一行**（避免把单行好答复清空），
于是"单条目批次"的回显永远不会被剥掉：`normalizeResult(1)` 通过，`cleanOutput` 不管，
`qualityCheck` 的 7 条旧规则也全过（中文、长度正常、换行守恒、没有新增反斜杠）。

### 处置

* `pipeline/translate/quality.js` 新增第 8 条规则 **`prompt-echo`**：从**调用方自己的模板**派生指令片段
  （`promptFragments`），译文含有而原文没有 → fatal。模板换了也覆盖，源串自带该片段则不算回显。
* `pipeline/translate/cache.js` 载入时**丢弃**回显值，`set()` 拒收：缓存里存着回显比没有更坏 ——
  `has()` 会认为该条已翻好，之后每一轮都把它写进游戏。
* `tools/unit-prompt-echo.js`：28 项断言，含 5 条真实污染对与 8 条真实正常译文（负对照）。

### 验证（游戏内）

修复后同一游戏重跑，日志出现 **`quality:prompt-echo:每行输出一条译文` × 17** ——
即门禁在真实数据上拦下了 17 次本会成为新的污染。`チェストウッド` 就是其中之一：
它此前正是被这样污染的，现在变成"安全失败"，字段保持原文。

## 4. 新发现：模型退化（word-salad）

### 证据

```
data/System.json      .terms.params[0]  "段法汉例"       ← 原文 最大ＨＰ（状态窗口标签）
data/System.json      .terms.params[1]  "构方容翻"       ← 原文 最大ＭＰ
data/Armors.json      [26].name         "汉例语子"       ← 防具名
data/resources/hiroka_tweet_list.json   .accounts[10].name "句构方容"  ← 游戏内社交账号名
技能说明              "敵全体の攻撃力を下げる。\n２回まで…" → "本解学篇义文明文\n汉例语子语式示译"
```

共 **351 处**游戏内值、**309 条**缓存值。值都是同一条循环上的窗口，循环由"翻译方法论词汇"
（汉语／例句／语法／句式／示译／句构／翻译…）组成。

### 触发条件（部分仍在复现）

源串里混入**技术性字符**时更容易触发：全角拉丁（`最大ＭＰ`）、数字与下划线
（`床1`、`伤患031`、`水母041`、`demo市民3_被写体ですね`）、字面 `\n`。本次施工期间
`最大ＭＰ` 仍能复现，说明**这一类不是纯历史遗留**。

### 处置

* `quality.js` 第 9 条规则 **`degenerate`**：以 35 个二元组为判据，要求同时满足
  "纯汉字 + 无标点数字拉丁 + 无常用虚词 + ≥4 字 + ≥3 个循环二元组"。
  ≥3 而非 ≥2，因为普通词也可能凑出一个（"文明"同时给出 `文明` 与 `明文`）；
  循环是闭合的，所以**回绕的那一对（`法汉`）也要算** —— 漏掉它会让 `段法汉例` 通过。
* `cache.js` 载入时丢弃、`set()` 拒收（与回显同一机制）。实测：`CACHE_PURGED_DEGENERATE 309`。
* `audit-lib.js` 新增该缺陷项，并区分"玩家可见内容"与"编辑器标签"，同时开始扫描
  `resources/` 下非 locale 目录（一个游戏把社交信息流放在那里，10 条乱码就藏在
  **管线既不提取也不回写**的文件里）。
* `tools/unit-degeneration.js`：47 项断言（10 条真实乱码 + 30 条正常值负对照）。

### 游戏修复（`凍堂ヒロカの隷雄譚`）

流程：`reset`（把污染字段恢复为备份里的日文）→ 管线重译（门禁生效）→ 审计。

```
污染字段：6 回显 + 341 退化 + 72 退化（阈值下调后追出）+ 12（管线不覆盖的文件）
最终审计：7 项全 ok，0 缺陷；对话覆盖 96.7% → 97.1%
```

其中 3 处模型无法给出可用译文（`最大ＨＰ`/`最大ＭＰ` 让模型退化），按游戏自身用词人工定值，
并在脚本里写明依据（如 `SYSTEM_MENU_LOAD` = `ロード` → "读档"，因为相邻的
`SYSTEM_MENU_SAVE` = `セーブ` → "存档"）。

## 8. 本轮的教训（补充交接报告第六节）

1. **两套判据必然漂移** —— 校验只有一处实现（`audit-lib`），别处只能调用它。
2. **"至少保留一行"的过滤在单条目上等于不设防** —— 边界只有 1 个元素时，所有"保留一个"的逻辑都失效。
3. **字符串遍历必须覆盖数组直接元素** —— 只走对象属性的遍历器会静默漏掉 `parameters[0]`、`terms.commands[i]`。
4. **缓存里的坏值比缺失更危险** —— `has()` 说"已翻好"，于是没有任何后续运行会修正它。修补必须在**载入**时做。
5. **退化不是历史遗留就能不管** —— `最大ＭＰ` 这类混合技术字符的源串仍会复现；门禁是必需的，不是保险。
6. **BOM 不是损坏** —— 引擎自己的加载器会剥离它，审计工具必须先剥再解析，否则 9 个健康文件被报成"无法解析"。
7. **没有备份就不能归因** —— 无备份的游戏上，任何"未解析的音频引用"都可能是游戏自带的问题，不能算作翻译破坏。
8. **会关机的脚本默认不该关机** —— 见第 7 节。
