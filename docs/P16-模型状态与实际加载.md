# P16 —— 模型状态必须反映"服务器实际加载了什么"

对象：`ui/MainForm.cs`、`ui/UiCheck.cs`。承接 `docs/P15-翻译对照面板.md`。

起因：一次实测发现"选了 1.8B，界面说已就绪，实际是 4B 在翻译，显存还被两个模型占满"。

---

## 一、当时的事实（实测）

```
GTX 1060 6GB   已用 5,899 / 6,144 MiB   剩余 131 MiB   利用率 90 %

pid 5136   启动于 10-11 21:02   Galtransl-v4-4B-2601.gguf   监听 18080   主机内存 8,253 MB
pid 10816  启动于 10-12 01:16   Hy-MT2-1.8B-Q8_0.gguf       监听 18080   主机内存 2,372 MB
```

**两个进程同时监听 18080** —— llama.cpp 给监听套接字设了 `SO_REUSEADDR`，而 **Windows 允许第二个绑同一端口**
（与 Linux 不同）。连探 10 次 `/props`，**10/10 都由 4B 应答**：1.8B 加载了、占着显存，却收不到任何请求。

一路都是绿灯，所以没有任何提示：新服务启动成功、程序日志写"已启动模型服务"、端口探测当然通（旧服务在答）、
状态标签显示"已就绪" —— 而标签显示的模型来自**下拉框的选择**，不是服务器实际加载的。

## 二、两处修复

### 1. 状态标签读服务器自报的模型（`AskLoadedModel`）

后台探测（每 ≥3 秒一次）在确认端口通之后，再发一个只读的 `/props`，取 `model_path` 的**文件名**：

| 情形 | 标签 | 颜色 |
| --- | --- | --- |
| 端口不通 | `状态：未启动` | 灰 |
| 通了，但与所选一致 | `状态：已就绪（Hy-MT2-1.8B-Q8_0.gguf）` | 绿 |
| **通了，但与所选不一致** | `状态：已就绪（实际 Galtransl-v4-4B-2601.gguf，非所选 Hy-MT2-1.8B-Q8_0.gguf）` | 橙 |
| 通了但读不到 `/props` | `状态：已就绪（模型未知）` | 绿 |

不一致时额外挂 tooltip，说明"翻译实际用的是前者"，并给出让选择生效的办法。这样"选了 1.8B 实际跑 4B"
这种谎话在界面上**藏不住**。

### 2. 启动模型前先接管被占用的端口（`PortOwners` + `KillProcessTree`）

`StartLlama` 在 `StopLlama` 之后若发现端口仍被占用，且占用者不是本程序启动的服务，就弹确认：

> 端口 18080 已被 PID 5136、PID 10816 占用，但它不是本程序启动的模型服务（它加载的是 Galtransl-v4-4B-2601.gguf）。
> Windows 允许两个服务同时监听一个端口，所以继续启动不会报错 —— 结果是两个模型都占着显存，而翻译仍然由旧的那个应答。
> 是 = 结束它们，然后加载「Hy-MT2-1.8B-Q8_0.gguf」

确认后**逐个结束所有占用者**（所以返回的是**列表**而不是单个 PID —— 两个进程占同一端口时，只杀一个端口仍然被占），
等端口真正释放再启动；若仍占用则明确报错，不再假装成功。

另外，`Process.Start` 之后会在 UI 线程等 1.5 秒**检查新进程是否立即退出**（显存不足、模型文件损坏都会这样）：
退出就报"启动失败（退出码 N）"并弹窗提示常见原因，而不是把「加载中…」留在屏幕上。

### 3. 不额外引入 shell

查端口占用者用 `iphlpapi.dll` 的 `GetExtendedTcpTable`（进程内询问，`MIB_TCPTABLE_OWNER_PID` 监听表：
DWORD 计数 + 每行 6 个 DWORD：state / localAddr / localPort / remoteAddr / remotePort / owningPid，
端口在 DWORD 低半部且是网络序，需按字节交换）；结束进程用 `Process.Kill()`。
比 `netstat -ano` + `taskkill` 更稳（不必穿过本地化的表头与状态词），也不引入两条 shell 命令。

## 三、自检

`_uicheck.exe` 从 104 增到 **115 项全绿**，新增：

```
PASS  找到 ApplyModelState / AskLoadedModel / PortOwners / _modelUp / _serverModel（反射）
PASS  未监听时显示未启动
PASS  实际模型与所选一致时不报警
PASS  实际与所选不一致时明确标出
        状态：已就绪（实际 Galtransl-v4-4B-2601.gguf，非所选 Hy-MT2-1.8B-Q8_0.gguf）
PASS  读不到 /props 时说未知
PASS  端口 18080 的监听者: PID 5136、PID 10816      ← 真实查询，两台都在
PASS  PID 5136 可解析为进程 / PID 10816 可解析为进程
PASS  无人监听的端口返回空列表
```

其中"端口监听者"是**真实调用**，不是模拟 —— 上面那行正是当场查出来的两个 PID。

## 四、部署

`ui/*.cs` 已同步，新 exe 落成 `GameTranslatorV3.exe.new`（与仓库构建 MD5 一致，**运行中的实例未动**）。
关掉程序后运行 `应用新版本.bat` 即生效。

应用后你会看到状态标签直接写出 **"实际 Galtransl-v4-4B-2601.gguf，非所选 Hy-MT2-1.8B-Q8_0.gguf"**；
点「启动模型」会弹窗询问是否结束那两个占用进程，确认后才会真正加载 1.8B。
