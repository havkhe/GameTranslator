# P12 —— 分组翻译队列（可追加、可续跑）

对象：`ui/MainForm.cs`、`ui/UiCheck.cs`（+ 新增 `build-uicheck.bat`）。
承接 `docs/P11-MTool规则与译文导入.md`。

起因：把"一次性批次"改成**可以不断往里加的分组队列** —— 先勾几个游戏成为第 1 组，第 1 组跑完
自动进第 2 组；左侧显示当前组数与状态；**运行中也能把单个游戏加进任意一组**。

| 新增落盘文件 | 仅 `work\queue.json`（新文件） |

回退：删掉 `work\queue.json`，或 `git checkout restore-point/pre-queue`（改前已打并推送该标签）。

## 二、界面

左侧由「工具栏 + 游戏列表」变成「任务队列 + 工具栏 + 游戏列表」：

```
split.Panel1 → pane
 ├ _list        (Dock.Fill)                       游戏列表（虚拟模式，未改动）
 ├ bar          (Dock.Top, 40)                    原有 7 个文件管理按钮（未改动）
 └ queueBox     (Dock.Top, 196)  「任务队列（按组顺序执行）」
     ├ top       摘要行：_lblQueue + 目标组下拉 _cmbTargetGroup
     ├ _queueTree TreeView：组 → 成员
     └ btns      TableLayoutPanel 3×2：6 个队列按钮
```

- 组节点：`第 1 组　[运行中 2/5]` / `[等待 0/3]` / `[已完成]` / `[已跳过 1]` / `[已终止]`
- 成员节点：`✔ 游戏A — 完成`、`▶ 游戏B — 等待`、`✖ 游戏C — 失败`、`⤼ …— 跳过`、`■ …— 取消`
- 摘要行：`队列：3 组 / 7 个任务　当前：第 2 组（1/4）`；空闲时 `未开始`；空队列给出操作提示

**用 TreeView 而不是第二个 ListView**：UiCheck 有一条"恰好一个 ListView 且 `VirtualMode=true`"的
不变量（UiCheck.cs），TreeView 不触碰它；语义上也更贴"可展开看成员"。

**有意不给游戏列表加"组"列**：`ApplyColumnWidths()` 与"列宽合计 ≤ 面板宽"按 5 列写死，
200 % 缩放下 状态 列曾被切过。组归属显示在队列面板与行 tooltip。

## 三、按钮与右键菜单

| 按钮 | 作用 | 运行中 |
| --- | --- | --- |
| 新建组并加入选中 | 把勾选游戏建成新组，追加到末尾 | ✅ 可用 |
| 加入选中到所选组 | 追加到右侧下拉选中的组 | ✅ 可用 |
| 移出选中 | 从队列移除（游戏与译文不受影响） | ❌ 禁用 |
| 清空队列 | 确认后清空（只清队列） | ❌ 禁用 |
| 跳过本组 | 放弃当前组剩余任务，直接进下一组 | 仅运行中可用 |
| 开始队列 | 从第一组开始；已完成的组跳过（可续跑） | ❌ 禁用 |

**右键菜单**（游戏列表）新增 `加入队列 ▸` → `加入新的组` + `加入第 N 组（M 个）`，
每次打开时按真实队列重建。这是"增添单个翻译子任务"的入口，**运行中同样可用**。

## 四、数据模型与持久化

```csharp
private sealed class QueueTask  { public string Dir, Name, Result = "", Note = ""; }
private sealed class TaskGroup  { public string State = "等待"; public readonly List<QueueTask> Tasks; }
```
`Result`：`"" | 完成 | 失败 | 跳过 | 取消`；`State`：`等待 | 运行中 | 已完成 | 已跳过 | 已终止`。

`SimpleJson` 只读"顶层数组 + 扁平对象"，所以 `work\queue.json` 与 `games-cache.json` 同构 ——
**每个任务一行**，组状态冗余在行上：

```json
[{"Group":1,"GroupState":"已完成","Ord":0,"Dir":"J:\\...","Name":"A","Result":"完成","Note":""}]
```

- 空组无法表示 → "新建组"必须至少含 1 个勾选游戏（按钮本就要求 ≥1）
- 读回时按 `Group`、`Ord` 升序重建；上次是 `运行中` 的组读回为 `等待`（异常退出不留假完成）
- `SaveQueue(path)` / `LoadQueue(path)` 带显式路径参数，供 UiCheck 用临时文件验证

## 五、运行：`RunQueue()`

```
确保模型就绪 → _running=true, _cts=new, ResetProgress()
逐组（跳过 已完成/已跳过/已终止 → 断点续跑）：
    组状态=运行中
    逐任务（内层每轮重读 Tasks.Count）：
        _cts 取消 → 停；_paused → 等；_skipGroupRequested → 跳出本组
        Result==完成 → 跳过（重跑只补没成功的）
        游戏不在列表 / g.Skip(已是中文) → 记「跳过」
        否则 await _runner.RunAsync(...) → 记 完成/失败/取消
        每步 SaveQueue() + RefreshQueuePanel() + RefreshList()
    组状态 = 已终止 / 已跳过 / 已完成
```

- **运行中追加为何安全**：`RunQueue` 是 UI 线程上的 `async void`，没有任何 `ConfigureAwait(false)`，
  所以每个续体都回到 UI 线程；按钮点击与它在同一线程交错执行。内层循环每轮读 `Tasks.Count`，
  于是加进**正在跑的那一组**的任务会被本次带上，加进**后面的组**的任务在该组开始时执行。
- **终止**（原按钮）：取消令牌 + `StopCurrent()`；当前组标 `已终止`，没轮到的组保持 `等待`
  → 再次「开始队列」即可续跑。**跳过本组**只放弃当前组剩余部分。
- 所有组都跑过时，`开始队列` 会先问"是否清空结果并重跑"。
- 复用：模型就绪检查抽成 `EnsureModelReadyAsync()`（原一次性批次也改用它，行为一致）；
  收尾状态复位抽成 `EndRun(label)`，一次性批次传 `批次`（**输出文案与之前完全相同**），队列传 `队列`。
