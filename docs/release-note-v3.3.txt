# GameTranslator v3.3 —— 云端可并发提速，归档游戏不再"显示已翻译、游戏里还是日文"

> **v3.3 新增一个设置项、修好两个会让整局白翻的缺陷。** 依然只有一个包
> （Vulkan 与 CUDA 12 两套后端都在里面），覆盖升级即可，`ui-settings.ini`、`api-config.json`、`work\` 都不在包里。

## 一、下载 / Downloads

- `GameTranslatorV3-v3.3.zip` —— **解压即用**：主程序 + 管线 + 工具 + 内置 node 与 ruby
  + **两套 llama.cpp 后端**（`llama\vulkan\` 与 `llama\cuda12\`），切换只改一个设置、离线即可。
- 覆盖升级即可，**设置与密钥不会丢**，已翻好的记录也不会被动。

## 二、新增：并发批次数（云端提速）

【设置…】里新增 **「并发批次数」**（1-64，默认 1 = 原来的串行行为）。
管线现在可以同时发出 N 个翻译批次；**只有顶层并发，批次内部的拆批与重试仍然串行**，
所以"译好一条立刻进缓存、只重试被拒的行、行数不对就折半重发"这些规则一条没变。

实测（600 行真实游戏语料，同一个接口、同一份输入）：

| 并发 | 耗时 | 吞吐 | 请求数 | 接口 token | 被拒/失败 |
|---|---|---|---|---|---|
| 1（原行为） | 82.0 s | 7.23 条/秒 | 88 | 32.3k + 13.0k | 18 / 20 |
| **8** | **14.0 s** | **42.37 条/秒** | 88 | 32.3k + 13.0k | 17 / 19 |

**5.9 倍，而且请求数与 token 完全相同、质量指标没有变化**——快出来的部分纯粹是原来闲置的接口容量。

> **只对云端 API 有意义。** 程序自带的本地 llama-server 是 `--parallel 1`，并发大于 1 只会让请求在它内部排队，
> 不会变快。云端建议 4-8。

## 三、修复：有加密归档的游戏被当成"散装"处理（翻了但没生效）

**症状**：程序显示已汉化、报告里替换了几十万处字符串，进游戏却还是日文。

**原因**：引擎判定先找散装的 `Data\*.rvdata2`、后找 `Game.rgss3a`。如果一个游戏**两者都有**
（常见于玩家自己用解包器解开过、或第三方工具留下的 `Data\`），它会被判成散装游戏：
补丁写进 `Data\`，而 **VX Ace 运行时优先读归档、散装文件被完全忽略**。实测一个游戏替换了 248,400 处、
报告成功，游戏里一个字都没变。

**现在**：**归档优先**，并且只认真正的 RGSSAD 容器（校验魔数与版本字节，1=VX / 3=VX Ace），
一个只是名字叫 `Game.rgss3a` 的残留文件不会把散装游戏拖进归档流程。判定逻辑抽成独立模块
`pipeline/engine-detect.js`，配 13 项单元测试覆盖各种组合。

> 本机扫描：带 RGSSAD 归档的游戏 129 个，其中 10 个目录（9 个标题）同时带散装 `Data\` —— 这些就是会踩坑的。
> 已经翻过但没生效的，**从 `data_原版备份` 还原归档后重跑即可**（配合下一节的修复，这次真的会重新解包）。

## 四、修复：解包副本不会随归档变化失效（"还原后重跑没用"）

修上面那个问题时发现的第二个缺陷：管线把归档解开到 `work\<游戏>_archive工作\unpacked\` 后会复用，
**但复用的条件是"这个目录存在"，而不是"归档还是当初那个"**。于是把归档还原成原版再重跑，
管线根本没重新解包，而是在上一轮那个已经被改过的副本上继续打补丁、又打包回去——
坏内容原样回来了。第一次修复时我就撞上了这一点：报告成功，坏文件名还在归档里。

**现在**：解包时记录**游戏里那个归档**的大小与修改时间，对不上就重新解包（日志写 `UNPACK_CACHE_STALE`）。

## 五、验证

- 单元测试：**20 个文件、504 项断言全部通过**（新增 `unit-engine-detect.js` 13 项、`unit-unpack-cache.js` 9 项）。

## 六、两条使用提示（不是本版改动，但会省你不少时间）

- **装了 MTool 的游戏**（目录里有 `winmm.dll` + `injectPath`，内容指向 `Tool\loaders\RGSSHook.dll`）：
  它的运行时会挂钩 `Window_Message`，用它自己的"日文→中文"词典逐句替换屏幕文字。**数据已经变成中文之后，
  它的词典查不到，会崩在 `Script 'Window_Message' line ... undefined method 'upcase' for nil`。**
  处理办法：把 `winmm.dll` 与 `injectPath` 改名（例如加后缀 `.mtool-off`）即可——汉化已经在数据里，
  不再需要它的运行时翻译。想改回 MTool 的翻译方式，就把文件名改回来并还原 `data_原版备份`。
  本机扫描：装了钩子的游戏 52 个，其中 4 个已被本项目翻过。
- **云端模型**：同一个免费接口上，`Index-Translate-35B-A3B` 与 `index-mt-9b` 在"日英混排"内容上表现稳定；
  但 `index-mt-2b` 在**英文为主的批次**里会整批失败（丢行号导致解析失败），
  行内混语时也常把日文半边留着。英文内容多的游戏建议用 9B 或 35B。
