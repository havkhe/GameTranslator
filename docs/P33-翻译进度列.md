## 一、任务进度栏：速度行改为「已译 条数/条数」

右侧「任务进度」面板的速度行，末尾原来是 `已知已译 1234 条`，现在改为：

```
速度：12.3 tok/s（近 15 秒）    45.6 条/分    已译 1234/15261 条
速度：45.6 条/分（近 15 秒，云端模式无 token 计数）    已译 1234/15261 条
```

- **分子（目前已翻译条数）** = 本次运行至今的累计已译条数（`_runEntriesBase + _lastProgressCount`）。
  它跨局累加，且单局内部用的是管线自己报的"命中缓存条数"，所以**重跑一个已翻过的游戏时分子会很快跳上去**。
- **分母（总需翻译条数）** = 本次运行交给它的所有游戏的条目数之和（新增 `RunWorkload()`）：
  - **正在跑的那一局**用**实时进度行**报的数字（那是本次抽取的规模，比盘上的报告新）；
  - 其它局用各自的 work 文件（`TryReadProgress`，见下节）。
  - **一个数都没有的游戏记为"未知"，不记为 0** —— 与下面预计时间里的做法一致；分母若静默漏掉一半，
    读起来就像一个更小的活儿。未知个数会跟在后面显示：`已译 1234/15261 条（另有 3 个游戏条数未知）`。
  - 结果**带缓存**：一趟要读最多 1 MB 的抽取文件 × 局数，而分母在一局跑动期间不会变，所以只在
    "当前局的条数"变化时重算。
- 分子**不做上限截断**：万一它超过分母，说明两个来源对不上，那是值得看见的事，不是该藏起来的事。

## 二、游戏列表的「翻译进度」列（用户第一次说的"已知已译"）

列表第 4 列（原「进度」）改为 **「翻译进度」**，内容从百分比改成一对计数：

```
975/9946        已译条数 / 需译条数
0/9946          一条都还没译，工作量照样看得到（百分比做不到这点）
```

原来的显示是 `45%` / `已译完`，**而且只在状态为「已汉化/部分汉化」时才显示**，其它游戏是空白。
现在只要这个游戏有可算的数据就显示计数。

### 两个数字从哪来

| | 来源 | 说明 |
|---|---|---|
| **已译条数** | `<stem>-translate-report.json` 的 `translated` | 管线自己的定义：本轮**命中缓存**的条目数，也就是"确实拿到译文"的条数 |
| **需译条数** | 后写入的那个文件：抽取文件的条目数，或报告的 `entries` | 见下 |

**为什么需译条数要挑"最后写的那个"**：一次运行会在**开始**时重写抽取文件、在**结束**时写报告。
如果中途被打断（或只跑了 `extract` 模式），抽取文件是新的、报告还是上一轮的，两者描述的条目集合**大小不同**。
实测 `Detective Girl of the Steam City`：报告写的是 1052 条（上一轮残留的集合），而盘上的抽取文件是 9946 条
—— 照报告显示就把工作量说小了 9 倍。所以规则是：

```
抽取文件存在 且 抽取文件不早于报告  →  需译条数 = 抽取文件里的条目数
否则                              →  需译条数 = 报告里的 entries
```

抽取文件的条目数用 `CountExtractEntries()` 数：该文件是 `pipeline/index.js` 写出的紧凑 JSON 数组、
每条以 `{"id":` 开头，数这个标记即可（用窗口那个扁平读取器去解析 1.2 MB 文档只会更慢，也不会更准）。

## 三、一条界限：我们**跳过**的游戏不显示工作量

`已是中文` / `自带中文` 的游戏是被窗口跳过的（别人翻的，或本来就是中文），
对它显示"0/9098"就是在描述一件不存在的工作 —— 实测 `【御光盟国汉化组】露出女子校生2` 正是如此
（状态 `自带中文`，而盘上残留的抽取文件有 9098 条）。所以新增 `ShowsProgress(状态)`：
只有我们**会去翻**的状态才显示（`未汉化` / `未汉化（已还原）` / `未汉化（英文原版）` / `部分汉化` / `已汉化（本项目）`）。

悬停提示里除了 `已译 / 需译 条（百分比）`，在状态不是我们自己的工作时还会补一句
「已译条数取自上一轮完成的运行」—— 因为这一轮若被打断，报告里的数字就是上一轮的，状态列才是游戏本身的事实。

### 实测各游戏会显示什么（用真实 work 文件按同一规则算出来的）

| 游戏 | 翻译进度 | 取值来源 |
|---|---|---|
| Detective Girl of the Steam City | `975/9946` | 抽取（9946）比报告（1052）新 |
| Bitch Dancer's Quest | `970/1050` | 报告最新 |
| Luxuria [ENG] | `138/190` | 报告最新 |
| 牧场Ver1.1 | `0/18929` | 抽取（18929）比报告新；分子取自上一轮完成的报告 |
| 【御光盟国汉化组】露出女子校生2 | （空） | 状态 `自带中文`，我们跳过它 |

> 写测试时踩到两个 C# 细节，记在这里：
> ① `Assert(got == c[2], ...)` 里 `c[2]` 是 `object`，而 **`string == object` 是引用比较** ——
> 两组期望 `""` 的用例之所以"通过"只是因为 `""` 被驻留。现在两侧都过 `Convert.ToString`。
> ② `new[] { 975, 9946, "975/9946" }` 无法推断类型（int 与 string 混用），要写 `new object[] { … }`。
