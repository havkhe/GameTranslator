# 字段白名单 —— 翻译哪些、为什么不动其余字段

本文回答一件事：**补丁会改写哪些字段，以及为什么另外一些字段即使被污染也不会被自动修复。**

来源是 `pipeline/extract/rules.js` 与两个对称的遍历器（`extract/mv.js` / `patch/mv.js`）。
提取与回写使用**同一批表**，所以补丁只可能改动提取阶段收集过的文本 —— 这是该设计的核心保证，
也是下面"无法自动修复"一条成立的同一个原因。

---

## 一、会被翻译的字段

### 1. 事件指令的文本参数（`EVENT_TEXT_CODES`）

| code | 含义 | 取哪个参数 |
|---|---|---|
| 401 | 显示文章（正文） | `parameters[0]` |
| 101 | 显示文章（说话人标题） | `parameters[0]` |
| 102 | 显示选项 | `parameters[0]`（数组，逐项） |
| 402 | 选项分支标签 | `parameters[1]` |
| 405 | 滚动文本正文 | `parameters[0]` |
| 111 | 条件分支的脚本/文本操作数 | `parameters[2]` |
| 320 / 324 / 325 | 改角色名 / 昵称 / 职业名 | `parameters[1]` |

### 2. 数据库字段（`TEXT_FIELDS`）

`name`、`nickname`、`description`、`profile`、`message1`–`message4`、`displayName`、
`currencyUnit`、`title`、`hint`

### 3. `System.json` 的 `terms`（`TERMS_KEYS`）

`basic`、`commands`、`params`、`messages`、`hint`

### 4. 本地化资源（`extract/resources.js`）

`data/resources/<locale>/*.json` 中除 `metadata/version/language/game/locale/name` 之外的字符串值。
**只读 `ja-JP`**：`en-US` 存同样的键英文文本，翻译它等于用我们的译文覆盖官方英文。

## 二、刻意不动的字段，以及各自的后果

| 字段 | 不动的理由 | 一旦被历史污染 |
|---|---|---|
| `note`（`META_KEYS` 全部） | 插件把它当元数据解析（`<CustomIcon: 5>`），翻译会改变插件行为 | **不可自动修复**，只能手工改 |
| `characterName` / `faceName` / `battlerName` / `parallaxName` | 引擎据此在磁盘上找文件 | 同上；且会立刻表现为加载失败 |
| 音频容器的 `name`（`titleBgm` / `battleBgm` / `victoryMe` / `defeatMe` / `gameoverMe` / `sounds[]` …） | 同上 | 同上 |
| `tilesetNames[]` / `animation1Name` / `animation2Name` | 同上 | 同上 |
| 非 `TEXT_FIELDS` 的键（插件参数、脚本、坐标等） | 不是给人读的文本 | 同上 |

### 为什么"不动"等于"不能自动修"

补丁按**文件里的现有文本**去缓存里查译文。被污染的字段里存的已经是译文（或垃圾），
它不再是缓存里任何一个键，于是：

* 提取阶段不会收集它（源数据来自 `data_原版备份`，那里是干净的日文）；
* 回写阶段查不到匹配，保持原样。

**结论：任何落到上述字段的污染都必须先把该字段恢复成原文，再让管线重新翻译；或者手工定值。**
（`docs/P8-后续修复报告.md` 里的 `reset-echo.js` + `restore` 流程就是按这条做的。）

## 三、会被翻译、但存在"安全失败"的情形

以下不是缺陷，是设计内的结果，记录在 `<游戏>-failures.json`：

| 标记 | 含义 |
|---|---|
| `quality:unchanged` | 译文与原文相同。专名、纯符号串（`…………っ♥`）走到这里 |
| `quality:prompt-echo` | 模型把提示词当答案回显 —— **被门禁拒绝，不会写入游戏** |
| `quality:degenerate` | 模型退化成一串"滑窗乱码"（见 P8 报告）—— **被门禁拒绝** |
| `already-chinese` | 原文已是中文，跳过 |
| `request-failed` | 答复无法解析成一行译文；重试一次后仍失败 |
| `*:too-short` | 多行/分段条目重组后长度不足原文 25% |

安全失败的结果是**该条目保持原文**，而不是写入错误内容。这是刻意的取舍：
宁可留一句日文，也不写进一句读不通的中文。

---

## 四、这份白名单的用途

1. **排除同类问题**：审计工具（`tools/audit-game.js`）只把"资源引用被改""控制代码被改"
   "出现提示词回显""出现退化乱码""文件解析失败""音频引用被翻译破坏" 判为缺陷；
   编辑器标签（`CommonEvents[N].name`、地图事件名）与"脚本块里剩下的假名"只作信息。

2. **判断一个新字段该不该翻**：若要新增可翻字段，必须同时确认
   (a) 引擎不拿它当键去查表/查文件，(b) 插件不解析它。两条都满足才加入 `TEXT_FIELDS`。

3. **解释"为什么有的字段只能手工修"**：见第二节末尾。
