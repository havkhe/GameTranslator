## 四、关键设计约束（继续施工必读）

### 4.1 备份机制（本轮重点修改）

```javascript
// pipeline/index.js
BACKUP_DIRNAME = "data_原版备份"

// 打包游戏：自动创建 + 始终从备份解包
ensureArchiveBackup()  → 若 data_原版备份\<归档名> 不存在则复制
                        → 始终从该备份解包（绝不从 live 读）

// 松散 MV/MZ：本轮新增同等保护
ensureDataBackup()     → 若 data_原版备份 无 json 则复制整个 data 目录
                        → 同时复制 resources/（否则有数据没对话）
                        → 若 live 已是中文则【拒绝备份】并报告
```

**为什么"拒绝备份"很重要**：用译文做"原版备份"是最坏结果 —— 之后每次翻译都从它读，会把中文再送进模型并报告成功。

### 4.2 字节级正确性的验证原则

RGSSAD 编解码**必须字节一致**，验证方式是**往返测试**：

```javascript
// pipeline/archive/repack-guard.js
repackSafely()  → 复制归档 → unpack+repack（不修改）→ 比对 SHA-256
                → 不一致则拒绝写入（REPACK_REFUSED）
                → GT_FORCE_REPACK=1 可强制覆盖
```

**关键教训（务必记住）**：

> **只做往返测试抓不到密钥 bug。**
>
> 未修改的归档上，v3 重打包是恒等变换 —— 无论密钥是否保留，存储字节都相同。
> 因为"用错误密钥重新加密正确明文"恰好得到与原来相同的密文。
>
> **只有修改一个成员才会暴露**：那时明文变了，错误密钥会产出与原归档不同的密文。
>
> 所以必须做**篡改测试**（改一个成员，验证只有该成员变化）。

### 4.3 不应翻译的内容（历史污染来源）

| 类型 | 例子 | 后果 |
|---|---|---|
| 资源文件名 | `titleBgm.name`、`bgm.name`、`battlerName` | 游戏无法加载资源 |
| 控制代码参数 | `\N<桃花>` → `\N<Peach Blossom>` | 角色名被替换成英文 |
| 提示词回显 | 译文 = "每行输出一条译文，不要编号…" | 界面显示提示词 |
| 凭空插入的代码 | `スマホ` → `\N[1]智能手机` | 显示错误的角色名 |

**`.bat` 文件的编码陷阱**（本轮踩过）：
```
.bat 由 cmd.exe 用系统 ANSI 代码页（GBK）读取，不是 UTF-8。
用 UTF-8 解码 GBK 文件会制造出"乱码"，得出错误结论。
验证脚本是否可用，应当【运行它】而非【阅读它】。
```

### 4.4 RGSSAD 加密要点

```
密钥序列:  key = (key * 7 + 3) >>> 0
每成员密钥: 归档可为每个成员指定独立密钥（MTool 生成的归档就是这样，
            实测某游戏有 616 个不同密钥）
            → 写入器【必须】沿用每个成员自己的密钥
            → 默认常量 0xdeadcafe 仅在调用方未提供时使用
v1/v2:     单一连续密钥流，透传原始字节
v3:        每成员独立密钥，必须解密后由写入器重新加密
```

## 六、本轮会话记录的教训（避免重复踩坑）

1. **只做往返测试抓不到密钥 bug** —— 必须做篡改测试。
2. **`.bat` 要用 cmd 的编码读** —— 否则制造乱码、误判脚本损坏；应运行而非阅读。
3. **假名比例不能判断语言** —— 日文游戏假名率可能很低；可靠判据是**与备份对比**。
4. **"文件名在磁盘不存在"不等于损坏** —— MV 部署时会给资源加尾随下划线（`.ogg_`）；且音频缺失可能是游戏自身问题。
5. **编辑器标签是安全的** —— `CommonEvents[N].name` 是事件名，只在编辑器显示，翻译它无害。
6. **补丁"正确地不动某字段"= 该字段污染后永久无法自动修复** —— 必须手工编辑。
7. **内联 PowerShell 会破坏正则/引号** —— 复杂脚本一律写成文件。
8. **`Tee-Object` 写 UTF-16LE** —— 读取时需按 UTF-16 解码。
9. **`Copy-Item` 通配符不覆盖** —— 用 `robocopy /MIR`。
10. **文件字节不同 ≠ 内容不同** —— 中文 JSON 未转义 vs 备份的 `\uXXXX` 转义；须解析后对比。

### 7.4 提示词文件（当前内容，已修正）

```
将下列每行日文翻译成简体中文。禁止翻译成英文，只输出简体中文。
如果原文含反斜杠开头的控制代码（如变量、角色名、颜色、图标等），必须原样保留，不要增加也不要删除；
原文没有控制代码时，译文中也不要出现。行数必须与输入完全相同。
每行输出一条译文，不要编号、不要JSON、不要解释。
{lines}
```

**切勿**在提示词中写出**字面控制代码**（如 `\N[1]`）—— 模型会把示例当成待翻译内容，
注入短条目。这是本轮修复的核心污染源。
