# GameTranslator v3 — 重设计说明

本文档是新版软件的**唯一需求与设计依据**。旧版本（v2.4-dev）作为功能基线和已验证算法来源保留。

---

## 1. 为什么重做

旧版的两个真实问题（不是猜测，是实测出来的）：

| 问题 | 证据 |
| --- | --- |
| **UI 功能入口混乱** | 30+ 个按钮平铺在一个面板；扫描/添加/模型/翻译/备份混在一起，无分组 |
| **管线是单体脚本** | `game-pipeline.js` 2132 行，提取/翻译/质检/补丁/归档编解码全在一个文件里，改一处影响全局 |

旧版的**算法本身大多是对的**（见第 5 节验证清单），问题在组织方式，不在算法。

所以 v3 的策略是：**重写架构与代码组织，移植已验证算法**。凡是能用实验证明正确的部分，不重新发明。

    translate/
      batcher.js              分组与拆半重试
      client.js               llama-server 客户端（含启动等待）
      quality.js              质检规则
      decoration.js           装饰剥离/还原
      glossary.js             术语表
    patch/                    回写
      mv.js
      vxace.js
    archive/                  归档编解码（移植）
      rgssad.js               v1/v2/v3 统一接口
    ruby/                     便携 Ruby 脚本（移植）
  tools/                      便携运行时
    llama/  node/  ruby/
  docs/
    使用说明.txt

**分层规则**：
- `ui/` 不得包含业务逻辑，只负责显示与转发
- `core/` 不引用 UI 类型
- `pipeline/` 通过标准输入输出与 `core/` 通信（进程隔离，崩溃不拖垮 UI）

## 4. MTool 规则对齐（A 方案）

从 MTool 自己的 `MTool_MapDataCache` 实测得出（`民間正義会社2`，2446 个参数字符串 + 312 个名称字段）：

| MTool 的行为 | 是否采纳 | 理由 |
| --- | --- | --- |
| 提取 `events[].pages[].list[].parameters[]`（对话/说话人/选项） | ✅ 采纳 | 核心剧情所在 |
| **纯汉字不过滤**（`神主`、`杜氏`、`警察官` 照提） | ✅ 采纳 | 实测：纯汉字里既有真日文名，也有中文；一刀切会漏翻 |
| 排除 `RPG::MoveRoute`、`EV001`、`door` 这类内部标识 | ✅ 采纳（**改进 MTool**） | MTool 会把它们收进去，属于噪声 |
| 只提事件参数、不提数据库字段 | ❌ 不采纳 | MTool 汉化的游戏菜单里道具/技能名仍是日文；我们覆盖更全 |
| 私有译文格式 `TrsData.bin` | ❌ 不可用 | 实测为自定义混淆，无明文、无法解析 |

**具体规则（v3 落地的三条）**：

1. **纯汉字保留** — 不使用"无假名即中文"的推断（该规则实测误杀 24%~52% 的真日文，如 `逃走成功`、`地下牢獄`）
2. **内部标识排除** — 匹配 `^RPG::`、`^[A-Z]{1,3}\d{3,}$`（如 `EV001`）、纯文件名（含扩展名）一律不进翻译队列
3. **事件参数全覆盖** — `401` 对话、`101` 说话人、`102` 选项、`402` 选项分支、`111` 条件文本、`320/324/325` 改名

## 8. 版本清理说明

用户要求"清理 git 与 GitHub 中不稳定版本的内容"。

需要说明可行性：
- **改写历史**（`git filter-repo` / 强制推送）会破坏所有已发布提交的哈希，任何已 clone 的副本会失配。这是不可逆操作。
- **安全的替代做法**：
  1. 把 `v2.4-dev` 上的可用成果合并到一个干净的 `v3` 分支
  2. 在 README / release 中标注 `v2.4-dev` 为**已被 v3 取代的试验分支**（不删除，保留可追溯性）
  3. 如确需移除，删除远端分支 `v2.4-dev` 即可（提交仍可通过哈希访问，不影响他人 clone）

在用户确认前，不执行任何改写历史的操作。
