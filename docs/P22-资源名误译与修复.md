## 一、结论

**是我们自己的补丁把图块表的文件名翻译了。** VX / VX Ace 把资源文件名存在数据里，其中图块表用的是
**数组**（`RPG::Tileset#@tileset_names`，九个图块贴图名）。而这个数组**绕过了 `TEXT_IVARS` 白名单**，
于是 `運動場` 被送去翻译、回写成简体 `运动场`，游戏便去找 `Graphics/Tilesets/运动场.png` —— 那个文件不存在。

- 受影响条目：`Tilesets.rvdata2` 的 **id=2 sheet[7]「運動場」**、**id=3 sheet[7]「学校アイテム」**（两次）
- **全库排查（12 个 VX / VX Ace 游戏）：只有这一局受过影响，现已修复**
- 那 31 局 MV/MZ 的坏窗口（P21）与此无关，是另一回事

## 二、根因：文本键的补丁分不清「名字」和「文件名」

`vxace_extract.rb` / `vxace_patch.rb` 里，字符串只在两种情况下会被当正文：

1. 作为某个对象的实例变量，且变量名在 `TEXT_IVARS` 里（`@name @description @message1…` 等）；
2. **任何 Array / Hash 里的裸字符串**（遍历时直接命中 `when String` 分支）。

第 2 条是漏洞：`@tileset_names` 正是「九元素字符串数组」，它的元素就这样进了翻译任务。

而**补丁是按文本查表的**（`byText`：原文→译文），所以它无法区分同一个字符串的两种身份：

| 同一个字符串 `運動場` | 字段 | 该不该翻 | 结果 |
|---|---|---|---|
| 一张地图的名字（`RPG::MapInfo#@name`） | 显示名 | **该翻** | 正确地译成 `运动场` |
| 一个图块表的贴图名（`RPG::Tileset#@tileset_names[7]`） | 文件名 | **绝不能翻** | 被同一本词典改坏 |

这就是关键：**只有字段能区分它们**，光看文本做不到。所以修法必须是「按字段拒绝」，而不是「按文本过滤」。

证据链（都在游戏目录里可复现）：

```
work\…-patch-report.json      {"engine":"VXAce","replacedStrings":1058,…,"Tilesets.rvdata2":{"replaced":6}}
work\…-translations.json      "運動場" -> "运动场"      （词典里确实有这条）
data_原版备份\Data\Tilesets.rvdata2   運動場×1  运动场×0   （2019 年的原版，干净）
Data\Tilesets.rvdata2                 運動場×0  运动场×1   （被改过）
Graphics\Tilesets\  文件名实为 運動場.png、学校アイテム.png（U+904B 52D5 5834）
```

## 三、代码修复

在两处 walker 里加**文件名拒绝名单**，按字段名拦截（数组类字段也在内）：

```ruby
RESOURCE_IVARS = %w[@tileset_names @tileset_name
                    @face_name @character_name @battler_name
                    @title_name @battleback1_name @battleback2_name
                    @animation1_name @animation2_name]
...
node.instance_variables.each do |ivar|
  next if RESOURCE_IVARS.include?(ivar.to_s)     # 名字像文件的一律不碰
```

- `@name` **不在**名单里：图块表的 `@name` 只是编辑器里的显示名（那一局它被正确译成「领域／外观／迷宫」，游戏照跑），
  而音频对象的 `@name` 早就被 `audio_object?` 排除了。
- **提取和补丁两边都必须加**。只改提取：词典里仍会有同名条目（来自地图名），补丁照样会写坏。
  只改补丁：白排一次翻译任务。两边的清单必须一字不差（文件里已互相注明）。

**回归测试** `pipeline/ruby/test-resource-ivars.rb`：故意让同一个字符串 `運動場` **既是地图名（该翻）
又是贴图名（不能翻）**，然后断言 8 件事——贴图名原样保留、地图名照翻、普通正文（角色名/描述）
照翻、图块表显示名照翻。`ruby test-resource-ivars.rb` → 全部通过（部署目录里也放了一份，同样全绿）。

## 五、我在过程中犯的一次错误（记录以免重犯）

第一版修复脚本 `repair-refs.rb` 用 **`类名#@id.变量名`** 当对齐键。问题是
`RPG::Event::Page::Graphic` **没有 `@id`**，于是同文件里所有该类的键都退化成同一个
`RPG::Event::Page::Graphic#.@character_name`，比对时把「最后一个备份值」写进了全部 128 个对象
（13 张地图，`Map006/012/017/018/020/024/033/034/035/041/046/054/055`）。

**已完全恢复**：把那 13 个文件从 `data_原版备份` 还原（原版是干净的），再用**修好的**补丁脚本重打一遍，
译文回到应有状态。现在的排查脚本改用「同序位置序号」做键（`类名#id.变量名#序号`），结构相同的两份数据
天然对齐，不再有键相撞的问题——这也是为什么这次全库扫描的结论（0 处）可信。

教训写在文档里：**对游戏数据做「按索引/按 id 对齐」的批量写入前，先确认对齐键在目标类里真的唯一**；
拿不准就先在备份副本上试，再动实盘。

## 八、以后遇到「启动报找不到文件」怎么办

1. 看报错里的路径：`Graphics/…` 或 `Audio/…` 下的名字如果是**简体中文**，基本就是这类问题；
2. 用 `scan-fields.rb` 扫一遍该游戏（它只看会指向文件的字段，且与备份逐位置比对）；
3. 修复：把相应文件从 `data_原版备份\Data` 还原，再用修好的补丁重打（词典还在，译文不会丢）；
4. 别用「按字符串替换」的方式修——同一个字符串可能同时是显示名和文件名。
