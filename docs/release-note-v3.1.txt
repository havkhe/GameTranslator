# GameTranslator v3.1 —— 云端 API 模式、英文版游戏、更诚实的界面（v2.3.2 以来第二个大版本）

> **v3.1 是 v3.0 的功能补充与修错版**：v3.0 换了新界面与新翻译内核，v3.1 把它跑不通的地方修好、
> 把它说错的地方改正，并加上"用 API Key 代替本地模型"这条路。
> **依然只有一个包**（不再分 RTX 版 / 普通版，那个差别只由 `download-llama.ps1` 的一个参数决定）。

## 一、下载 / Downloads

- `GameTranslatorV3-v3.1.zip` —— **解压即用**：主程序 + 管线 + 工具 + 内置 node 与 ruby + Vulkan 版 llama.cpp。
  - RTX 20 / 30 / 40 / 50 系想换成 CUDA 版，解压后在该目录执行一次：
    `.\download-llama.ps1 -Dest .\llama -Backend cuda12`
  - 其它（含 6 GB 显存级别的老卡）用包内自带的 Vulkan 版即可：`.\download-llama.ps1 -Dest .\llama -Backend vulkan`
- 模型 `.gguf` 需另行取得（放到设置里的「模型目录」）。4B 级（如 Galtransl-v4）质量更好，1.8B 级（如 Hy-MT2）显存占用更小。
- 覆盖升级即可，**设置与密钥不会丢**：`ui-settings.ini`、`api-config.json`、`work\` 都不在包里。

## 二、v3.1 新增的功能

- **云端 API 模式**：在【设置…】→「云端 API」里填接口地址 + API Key 即可**不用本地模型**翻译。
  - **自动识别模型**：点「刷新列表」读接口的 `/models`，只留下**能翻译文本的大语言模型**（向量、重排、
    视觉、语音合成/识别、图像生成这些一律不列，选了它们每一条请求都会失败）；
  - **免费额度用完自动换模型**：接口回 `403 AllocationQuota.FreeTierOnly` 时自动切到模型链的下一个，
    **并重试同一条请求**，所以批次里不会因为换模型而出现"未翻译"的条目；
  - **模型名不对也能自愈**：端点回"模型不存在"时同样换下一个；
  - **用量核算**：每局结束打印接口上报的真实 token 用量，用来估算免费额度够不够。
- **英文版游戏现在会被翻译**。以前英文原版的数据（含全部对白）在提取阶段就被丢掉，翻完只有菜单是中文。
- **界面说实话了**：状态列区分 `未汉化` / `未汉化（英文原版）` / `未汉化（已打包）` / `未汉化（已还原）` /
  `部分汉化` / `已汉化（本项目）` / `已是中文` / `自带中文`；**我们跳过的游戏不再对它们显示"进度"**。
- **翻译进度看得很清楚**：列表新增「翻译进度」列 = `已译条数/需译条数`（例如 `975/9946`），
  速度行显示 `已译 1234/15261 条`（替换原来只给一个数字的「已知已译」）。
- **搜索与排序**：左上「搜索游戏名」边打边筛（空格分隔多词、要求全部命中）；**点列标题排序**（游戏/引擎/
  翻译进度/状态，再点一次反向，列头带 ▲▼）。筛选只影响显示，不影响要跑哪些游戏。
- **任务队列的下拉就是总览**：展开即看到每一组的状态、完成/总数与成员名单，默认选第 1 组。
- **VX / VX Ace 归档游戏的引擎能被认出来**：按归档头（RGSSAD 版本 1 = VX，版本 3 = VX Ace）判断，
  不再因为"没有散装 data 目录"而显示不出引擎；只有归档、启动器不叫 `Game.exe` 的游戏也能扫到。
- **被打包进 exe 的游戏会被识别并说明**：状态写 `未汉化（已打包）`、引擎写 `MV（已打包，需先解包）`，
  去翻它会在日志里明确告诉你数据在哪个 exe 里、需要先解包——而不是沉默。见下面「已知限制」。

## 三、修掉的问题

- **云端 API 根本跑不起来**（三个各自独立的原因）：对 https 端点发的是明文 HTTP（整轮 `read ECONNRESET`）；
  翻译模型 `qwen-mt-*` 不接受 `system` 角色（400）；云端从没发过关闭思考链的参数。
- **模型下拉框选了不生效**：云端模型链是从设置里的字段拼的，而下拉框的选择从来没被记录，选完等于没选；
  取不到云端列表时下拉框还会变成一行禁用提示（"无法切换"）。现在选择即生效、取不到列表就退回已配置的模型链。
- **批次回包错位**：多行回包没有编号锚点，数量对得上也可能整体位移（曾导致一局 4,634 条里 911 条对错人）。
  现在每次请求都带行号并要求逐行回编号，没有编号的多行回包直接拒收并拆分重试。
- **VX Ace 把不带假名的日文名当"已是中文"跳过**（`斬撃/必殺技3`、`神父` 这类），菜单/技能名因此长期是日文。
- **语言判定把英文版判成"自带中文"**，整局被跳过、永远不翻。现在按**玩家读到的文本**判语言，而不是按目录字节。
- **`System.json` 因为带 UTF-8 BOM 被整份跳过**（菜单词、存读档提示、技能类型与属性名都没被翻译）。
- **扫描的四个毛病**：漏掉只有 `Game.rgss2a`/`Game.rgssad` 的游戏；游戏内部的子目录（`game1`/`game2`/工具目录）
  被当成独立游戏重复登记；「扫描全部路径」会跳过"已经有游戏的根"，导致漏扫的游戏**永远补不进来**；
  「扫描文件夹」扫完不保存也不刷新。
- **速度与进度**：tok/s、条/分、完成时间预计、本局已译条数——v3.0 已经做了，但当时界面上还是旧式显示；
  这次一并确认生效并写进了检查项。

## 四、已知限制（如实写在文档里）

- **打包进单个 exe 的游戏（Enigma Virtual Box 这类）本工具读不到里面的 `www/data`**：
  需要先用第三方工具解包（例如 `pip install evbunpack` 后
  `evbunpack "游戏\Game_boxed.exe" -o "输出目录"`），把 `www/data/*.json` 释放出来再来翻译。
  本工具**没有**内置这个解包器（那是逆向该容器格式的工作），但它会明确告诉你这一步。
- **VX / 归档游戏目前仍只按字节判语言**：`.rvdata2` 里嵌着整份 Ruby 脚本，字节里的拉丁比例不能说明语言，
  所以这类英文版可能仍被当作中文。已写进 `docs/P32` 的"已知限制"一节并由单测钉住。
- **云端服务商有内容审核**：露骨对白会被拦（实测约 4%，且重试也一样），被拦的条目会留在失败记录里、
  不会写成译文。批量翻成人向作品建议用本地模型（本地没有审核）。
- **云端模型名/额度**：`qwen-mt-plus` 这类翻译模型不接受 `system` 角色、也不吃 `enable_thinking` 参数，
  工具已按各自特性适配；不同账号能用的模型不同，以「刷新列表」拉到的为准。

## 五、安装 / 更新

1. 解压覆盖到旧目录（或新目录）即可；**设置与密钥不在包里**，升级不会覆盖它们。
2. 双击 `GameTranslatorV3.exe`：首次使用在【设置…】里填「模型目录」与「扫描路径」。
3. 主程序与界面源码随包提供（`ui\`），改了界面用 `build-ui.bat` 重新编译，
   再用根目录的 `应用新版本.bat` 应用（它在程序运行时拒绝替换，避免打断正在跑的翻译）。
