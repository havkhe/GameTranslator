## 三、服务端层面

`llama-server --help` 里有三个相关开关：

```
--jinja / --no-jinja          （默认 enabled，所以请求里的 chat_template_kwargs 会被采纳）
-rea, --reasoning [on|off|auto]（默认 auto）
--reasoning-budget N          （0 = 立刻结束思考）
```

应用启动模型时传的参数（`ui/MainForm.cs:2852-2858`）是：

```
-m <模型> --host 127.0.0.1 --port <端口> -c 4096 -ngl 99 -b 1024 -ub 256 -t 4
--poll 0 -fa on -ctk f16 -ctv f16 --parallel 1 --temp 0.3 --top-p 0.8 --metrics --no-webui
```

**没有** `-rea`／`--reasoning-budget`。也就是说关闭思考目前只靠请求体那一个参数——够用（`--jinja` 默认开），但如果想做成"服务端级别的保险"，可以在这行参数里加 `-rea off`。这需要改 UI 并重新编译，**本次未改**。

## 四、顺带发现：10-10 04:11–04:52 有一批"整局 0 条"的坏窗口

扫全部 68 份 `*-translate-report.json` 发现：**31 局的 `translated` 是 0**，而且时间**集中在 10-10 04:11 到 04:52** 这一批，之后（10-10 04:50 起、以及今天 10-11 的全部运行）都正常。它们的 `-failures.json` 里**每一条都是 `request-failed`**，不是被质量闸门否掉：

| 局 | 条目 | 失败 | 失败类型 |
|---|---|---|---|
| `_OreNo小屋…魔法少女` | 26,163 | 26,150 | 100% `request-failed` |
| `SENNYU5` | 16,762 | 16,727 | 100% `request-failed` |
| `借金JK人生NTR` | 10,202 | 10,138 | 100% `request-failed` |
| `_同人…鉄脚` | 7,728 | 6,532 | 100% `request-failed` |
| `_同人…静 北国`（同批，23%） | 6,165 | **137** | 混合：`already-chinese` 62、`code-invented` 27、`request-failed` 19、`prompt-echo` 15 |

关键对照：**同一批里 `静 北国` 的失败是正常的门禁类失败**（模型确实答了、只是答得不好），说明当时模型是活的 —— 所以这个窗口**不是思考链的问题**，而是特定几局"请求全部失败"的原因（当时正是两个 llama-server 抢 18080、显存占满的时期，服务器不稳定最像）。错误日志 `errors.log` 只留到今天，已无法回溯那一批的原始报错。

**复测（`recheck-game.js`）**：从 SENNYU5 抽 300 条，走生产管线、写到独立缓存（**不碰该局的 `translations.json`**）：

```
用时 618.7 秒   通过 232/300（77%）   请求 188   拆分 2
失败：168×stray-chars:︎   19×stray-chars:︎|unchanged   13×prompt-echo   11×unchanged
```

- **`request-failed` 一条都没有** → 那 31 局今天可以直接重跑，坏窗口是当时的状态问题，不是这些游戏本身的毛病。
- 译文质量正常：`伊織→伊织`、`鍛錬１→训练1`、`ALICEの情報④→ALICE的信息④`、`K-02牧場へ→前往K-02牧场`、`ポーションを３個手に入れた！→我已经拿到了3个药剂！`，引号/括号/数字都对。
- **但慢得离谱：29 条/分，只有 `_OreNo小屋` 的 146 条/分的 1/5。** 原因就是 P19 那个闸门误判：SENNYU5 有 22.7% 的条目带 `❤︎`（U+FE0E），被判 `stray-chars` 后进入重试阶梯，**批处理被打散成单条请求**（188 请求 / 300 条 = 1.6 条/请求，正常是 8 条/请求）。

也就是说，`quality.js:224` 那一行未实施的改动，代价不只是"约 2% 的条目永远译不出"，还有**带装饰符的游戏要慢 5 倍**。SENNYU5、牧场Ver1.1 这两局合计 32 万字，按这个速度仅它们就要 **约 14 小时**，改完约 3 小时。

## 五、遗留的一处小缺口（不影响现状）

仓库根目录的 `game-pipeline.js` 是 v2 的旧入口，它自己也直连 `/v1/chat/completions`，但**没有带 `enable_thinking:false`**，也没有 v3 的其它修复。

- 它**不在部署目录里**（`D:\GameTranslatorV3` 下没有这个文件）；
- 生效路径是 `ui-settings.ini` 里钉死的 `PipelineJs=…\pipeline\index.js`；`Settings.cs:116` 只在 v3 文件缺失时才回退到 `game-pipeline.js`。

所以它是**潜在**缺口而非当前问题。要么给它补上同样的参数，要么在文档里明确它是废弃入口。

## 六、建议

1. **思考链已在唯一生效路径上全局关闭**，无需再动。
2. 想更保险，可在 `ui/MainForm.cs:2852` 的启动参数里加 `-rea off`（需重新编译并"应用新版本"）。
3. **那 31 局直接重跑即可**，不必特殊处理。
4. **建议尽快实施 `quality.js:224` 的一行改动**（把 U+FE0E 移出乱码字符类）：在 SENNYU5 的实测里，它同时决定 23% 的条目能不能落地、以及这一局是跑 3 小时还是 14 小时。
