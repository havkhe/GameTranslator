## 一、问题

点「刷新列表」后，云端模型下拉框里混进了**根本不能翻译文本**的模型。

百炼（`compatible-mode/v1`）的 `GET /models` 返回的是它服务的**全部**模型，而不是可对话的模型：

| 类别 | 例子 |
|---|---|
| 文本向量 | `text-embedding-v3`、`text-embedding-v2`、`bge-m3` |
| 重排 | `gte-rerank-v2` |
| 视觉语言（VL） | `qwen-vl-max`、`qwen-vl-plus`、`qwen2.5-vl-7b-instruct` |
| 语音合成 / 识别 | `cosyvoice-v1`、`sambert-zhide-v1`、`qwen-tts`、`paraformer-realtime-v2`、`sensevoice-v1`、`whisper-large-v3` |
| 图像 / 视频生成 | `wanx-v1`、`wanx2.1-t2i-turbo`、`stable-diffusion-xl`、`flux-schnell`、`kling-v1`、`qwen-image-edit` |
| 音频理解 | `qwen-audio-turbo` |

选中其中任何一个，翻译任务会**每一条请求都失败**（这些端点不接受 `chat/completions` 的文本翻译语义，
或者干脆不认这个模型名）。列表里出现它们，等于给用户挖坑。

## 二、做法

一处判据，两边各存一份（窗口不能 `require` 管线文件，反之亦然，所以两边保持一致）：

```js
// pipeline/translate/client.js
const NON_CHAT_MODEL =
  /(embed|rerank|gte-|bge-|clip|whisper|sensevoice|paraformer|cosyvoice|sambert|\btts\b|\basr\b|\bvl\b|vision|ocr|wanx|stable-diffusion|sdxl|flux|kling|image|avatar|speech|voice|audio)/i;
function isTextModel(id) { return !NON_CHAT_MODEL.test(String(id || "")); }
```

```csharp
// ui/MainForm.cs —— 与上面逐字一致（RegexOptions.IgnoreCase）
private static readonly Regex NonChatModel = new Regex(
    @"(embed|rerank|...|voice|audio)", RegexOptions.IgnoreCase);
private static bool IsCloudTextModel(string id) { return !NonChatModel.IsMatch(id ?? ""); }
```

- `client.js` 的 `listModels()` 过滤：`list.map(m => m.id || m.name).filter(id => id && isTextModel(id))`
  ——**管线自己拉列表时也不会拿到非文本模型**（供 `tools/` 与将来任何非 GUI 调用）。
- `MainForm.ParseModelIds()` 过滤：窗口的「刷新列表」只填文本模型。

保留 `qwen-vl-*` 之类的取舍说明：VL 模型能接受文本输入，但它的用途与计费是图形理解，
在纯文本翻译链里没有理由出现；`\bvl\b` 因此按非文本处理。识别过程中**不误伤**常见的对话模型
（`qwen-plus`/`qwen-max`/`qwen-turbo`/`qwen-mt-plus`/`deepseek-v3`/`glm-4-plus`/`qwq-plus`/`qwen3-coder-plus` …）。

## 三、顺带修掉的两个坑

这两个是同一批调试里暴露出来的，一起记在这里：

### 1. 本地 gguf 名字落进了云端模型字段

部署目录的 `ui-settings.ini` 里曾经是：

```
UseApi=1
ApiModel=Galtransl-v4-4B-2601.gguf        ← 本地模型名，云端接口不认识
```

用户在「云端 API」还没重新拉列表时保存设置，下拉框里放的是**本地 gguf 名**，于是被写进了 `ApiModel`。
后果：云端模式下每一条请求都 404。

三处一起加固：

- `ui/Settings.cs` 的 `Load()`：读到 `.gguf` 结尾的 `ApiModel` 就**改用模型链的第一项**（默认 `qwen-mt-plus`）。
- `ui/MainForm.cs` 保存时：下拉框里是 `.gguf` 就**弹提示并拒绝**把它当云端模型，保留原模型名。
- `pipeline/translate/client.js`：新增 `isModelUnavailable(status, body)`，端点回「模型不存在」时
  **自动切到链上的下一个模型**（与「额度用完」同一条换模型路径），并打日志
  `…该端点不认识这个模型名，继续用 <next> 翻译`。这样即使 ini 里真有错名，任务也能自愈。

区分「模型名无效」与「密钥无效」是必须的：`401 / InvalidApiKey` 属于密钥问题，**不能**当作换模型的理由
（换了也还是 401，只会白跑）。所以 `isModelUnavailable` 先排除 `api key / unauthorized / invalid token / permission`
这类字眼。

### 2. 部署目录里那份落后的 UI 源码

`D:\GameTranslatorV3\` 根目录平铺着一份旧 `*.cs`（`MainForm.cs`/`Settings.cs`/`UiCheck.cs` 都比仓库旧），
而部署根的两个构建脚本 `build-ui.bat`/`build-uicheck.bat` 里写的是 `ui\...`。这次一并**对齐**：

- 新建 `D:\GameTranslatorV3\ui\`，放入仓库当前的 8 个源文件（部署从此能自己构建）。
- 根目录那份旧的 `*.cs` 移进 `D:\GameTranslatorV3\_src-backup-20261011\`（保留、不删，可回退）。
