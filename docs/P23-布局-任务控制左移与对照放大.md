## 一、改了什么

| 区域 | 改前 | 改后 |
|---|---|---|
| **任务控制**（10 个按钮） | 右列中间一行，AutoSize 约 104 px | **移到左列底部**（游戏列表下方），仍为三列按钮网格 |
| **日志 / 错误** | 右列底部，Dock=Fill（吃掉剩余高度） | **移到左列底部**（任务控制下方），固定 130 px |

改后的结构：

```
左列（宽 640）                        右列（宽 574）
 ┌ 任务队列（196）                    ┌ 翻译模型（自动高度）
 ├ 工具栏（40）                       ├ 任务进度（180）
 ├ 游戏列表（占剩余）                  └ 翻译对照（占右侧剩余的全部）
 ├ 任务控制（自动高度）                     ├ 原文框 48 / 译文框 48
 └ 日志（130）                             └ 历史列表 ← 约 10 行
```

## 二、为什么这么放

原来右列自上而下是：模型 → 进度(210) → 对照(200) → 任务控制(104) → 日志(占满剩余)。
**每一个像素都是从那一个"能读译文的地方"里抠出来的**：对照框只有 200 px，里面还要塞两个 36 px 的
框和一个 28 px 的工具条，留给历史列表的只剩 **约 56 px（两三行）**——这就是"框太小、看不到范围"的根源。

按钮和日志都是"操作与反馈"，不需要宽度也不在该被盯着的区域，所以整列挪到左边（左列比右列还宽，
按钮网格更宽松）；右列只留"模型 / 进度 / 译文"三件事，对照框自然吃满。

## 三、实测前后（UiCheck 读到的真实像素）

| 指标 | 改前 | 改后 |
|---|---|---|
| 翻译对照容器高 | 200 px | **411 px** |
| 对照历史列表高 | 约 56 px（≈2 行） | **249 px（≈10 行）** |
| 原文/译文框高 | 36 px | 48 px |
| 日志容器高 | 随窗口伸缩（约 167） | 130 px（左侧固定） |
| 任务控制位置 | 右列 | 左列（与游戏列表同一面板） |
| UiCheck | 133 项 | **144 项，全部通过** |

新增的 11 项断言都是结构性的、不依赖眼睛：任务控制与游戏列表**同属左侧面板**、日志也在左侧、
翻译对照**在另一侧**、对照容器 `Dock=Fill` 且比日志高、原文/译文框 ≥44 px、**历史列表 ≥200 px**。
判定"左/右"的办法是往上找到父容器为 `SplitterPanel` 的那个控件——第一版我拿"最顶层祖先"比，
两边都落到 SplitContainer 上，于是误判，已改（见 P22 的教训：对齐键/判定基准要选对）。

## 四、布局规律（以后再改布局照这个来）

WinForms 里**停靠顺序 = 控件集合的倒序**：最后 Add 的那个先摆。

- 面板里想从下往上排，就按 **"填充的先进，顶部的最后进"**：
  `Controls.Add(左侧面板)` 里当前顺序是 `_list(填充) → 任务控制(底) → 日志(底) → 工具栏(顶) → 队列(顶)`，
  于是自上而下正好是：队列 / 工具栏 / 列表 / 任务控制 / 日志。
- 两个都 Dock=Bottom 时，**后 Add 的更靠底**，所以日志放在任务控制之后 → 日志在最下面。
- 右列同理：`对照(填充) → 进度(顶) → 模型(顶)`。

## 五、怎么生效

```

复制为 .new             →  （部署目录）GameTranslatorV3.exe.new   （本次已完成）
```

`.new` 已就位（19:05 构建，与仓库构建逐字节一致）。想看到新布局，等当前批次告一段落，关掉窗口
再跑一次 `应用新版本.bat` 即可。

## 七、还能更大吗

对照框现在拿到的是"右列除模型(约 90)与进度(180)之外的全部"。想再大一点，按性价比依次是：

1. **把窗口拉高**（窗口本身可缩放，拉到 900 高对照就能到约 530 px）；
2. 继续压任务进度面板：它是 9 行短标签，可再压到 150（约 +30 px）；
3. 日志压到 110（约 +20 px）；
4. 若希望自己拖着调，可以给"对照 / 日志"之间加一条分隔条（SplitContainer）——本次没做，
   因为分隔条在 200% 缩放下容易出现难拖的细缝，而固定高度更稳。
