# P25 —— VX Ace 覆盖率缺口：不含假名的日文名被当成"已是中文"跳过

生成时间：2026-10-12
分支：`v3-p1`
起因：`LewDemon Academy` 这类 VX Ace 游戏"UI 说已汉化、游戏里菜单/名词仍是日文"
新增单测：`tools/unit-vx-skip.js`（19 项）

---

## 一、先纠正我上一次的判断

我上一轮说"我们只抽取到 893 条、游戏里约一半日文字符（主要是对白）从未进过翻译任务"——**这个说法测错了**。
逐条实测后真相是：

| 测的东西 | 实测结果 |
|---|---|
| 对白（事件指令 401/405，玩家真正读的） | 原版 **2,475 行里只有 16 行带假名（0.6%）** —— **这一局的对白本来就是中文的**（汉化版或 MTool 写入过），根本不是"对白没抽到" |
| 提取器的走查覆盖 | Ruby 走查 905 条候选；被规则过滤 0 条 |
| **被判为"已是中文"跳过** | **226 条** ← 真正的缺口在这里 |
| 其余"未收集"的 823 条 | 显示图片文件名 370、开发者注释 213、跳转标签 181、行走图文件名 40 —— **全都不该翻译**（翻了会丢图/跳错） |

所以**不是提取器抽不到，而是过滤器把日文名当成中文丢掉了**。

## 二、根因

`pipeline/extract/vxace.js` 的 `isChineseLike()`：只要"不含假名、汉字占一半以上"就判定为已是中文。

但日文里**用汉字写的词**太多了：`剣` `盾` `薬` `回復魔法` `斬撃/必殺技2` `敵ダメージ` —— 它们和中文用同一批字，
判据完全分不开。MV 那边早就修过这个问题（`translate/index.js` 的 `mayBeChineseAlready` 只跳过**长句**
`CHINESE_PROSE_MIN = 12`，短词照送），**VX 这条路一直没有同步这个改动**。

实测：LewDemon 的 905 条候选里 **226 条**因此被丢掉，而且丢的正是**战斗/技能/道具名**——
玩家在菜单和战斗里一眼就能看到的文本。这就是"菜单名词没翻"的确切原因。

## 三、修复

`isChineseLike(s, minLength)` 增加长度门槛，提取时传 `CHINESE_PROSE_MIN = 12`：
不含假名的汉字串**只有达到长句长度**才算"已是中文"，短词一律送翻译。与 MV 侧规则一致。

| | 修前 | 修后 |
|---|---|---|
| 走查候选 | 905 | 905 |
| 因"已是中文"跳过 | **226** | **0** |
| 进入翻译任务 | 679 | **905**（+251 条不含假名的名字类） |

救回来的样例：`格闘/物理`、`斬撃/炎`、`刺突/氷`、`突撃/必殺技1`、`敵ダメージ` …（正是菜单与战斗文本）。

规则单测（19 项）覆盖了：短日文名必须送（`剣`/`回復魔法`/`斬撃/必殺技2`）；真·中文长句仍要跳过
（`你已经获得了三个药剂，请小心使用它们。`）；带假名的一律不跳；短句即使像中文也照送；`HP`/空串不受影响。

## 四、这是否是"UI 说已汉化、游戏里没汉化"的原因

**是原因之一，但不是全部**，到现在三类都清楚了：

| 类型 | 成因 | 状态 |
|---|---|---|
| A | 进度列读的是**上一次的报告**：数据已被还原成原版，列表却显示"已译 100%" | 已修（P24/本轮） |
| B | **不含假名的日文名被跳过**：菜单/技能/道具名从未进翻译任务（对白本身已有中文） | **已修（本文件）** |
| C | 该游戏同时装了 **MTool**（`TrsData.bin` + `与工具一同启动.bat`）：若从 MTool 启动，显示的是**它自己的字典**，可能覆盖我们写进数据的译文 | 需人工确认：直接启动 `Game.exe` 对比一次即可判断 |

## 五、受影响范围与重跑

跑过 VX 路径的一共有 11 条记录（LewDemon、民間正義会社2 観光バス編、Magical Girl Sarah、Kana Saw、
Luxuria、Country Girl Keiko 等）。它们的缓存**仍然有效**，而且被跳过的那些日文名**还在数据里**，
所以**不需要还原、直接增量重跑**即可：抽取出这 200~300 条新条目 → 翻译 → 打补丁。

重跑时机：程序正在翻译时不要抢模型（本轮没有动它）；跑完这批后在界面里勾选它们、点「开始汉化选中」即可。
