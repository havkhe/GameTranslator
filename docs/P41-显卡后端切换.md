## 一、为什么要切换：CUDA 12 的包不支持 GTX 10 系

CUDA 12 的预编译包**只带 sm_70 及以上的内核**（Volta / Turing 起，即 RTX 20 系往上）。
GTX 10 系是 Pascal（sm_61），装上 CUDA 版后 llama.cpp 会**静默退回 CPU**——能跑，但慢得多。
所以这台机器（**GTX 1060 6GB**）正确选择是 **Vulkan**，而 RTX 机器用 CUDA 12 更快。
以前只能手工执行 `download-llama.ps1` 把整个 `llama` 目录换掉，两套不能共存。

## 二、两套并存 + 一键切换

**布局**（包里就是两种都有）：

```
llama\
  vulkan\llama-server.exe    ← 默认：老 NVIDIA / AMD / Intel 都能用
  cuda12\llama-server.exe    ← 需要 sm_70+，自带 cudart64*.dll
  BACKENDS.txt               ← 两套各是什么、怎么切、怎么更新
```

切换是**一个设置 + 一次重启**，不下载、离线可用：

1. **窗口里**：模型行最右边新增按钮 **「后端：Vulkan / 后端：CUDA 12」**（点击即切换）。
   - 有服务在跑且**没有翻译任务**时，自动「停止 → 启动」，切换立刻生效；
   - **翻译进行中会拒绝**（服务器正在为当前这一局服务，停掉它会让整批失败）；
   - 所选后端的文件夹不存在时，**提供一键下载**（在窗口进程内直接下载 + 解压，见下）；
   - 切到 CUDA 12 前会检查显卡：没有 sm_70+ 的 NVIDIA 卡会**先警告**再切；
   - 状态行（任务进度栏「模型：… 端口：… 」那一行）末尾会写 **后端：vulkan / cuda12**，
     如果所选后端与实际安装的不是一个，会跟一句「（实际：…）」；文件夹缺失则写「（未安装：…）」。
2. **根目录里**：双击 **`切换显卡后端.bat`**（菜单式），或执行
   `.\switch-backend.ps1 -Backend cuda12`（不带参数则只显示当前状态与安装情况）。
   两者都只改 `ui-settings.ini` 里的 `LlamaBackend=` 一行，**其它设置原样不动**。

**向后兼容**：老的单目录布局（`llama\llama-server.exe`）**照旧可用** —— 找不到 `llama\<backend>\` 时
自动回落到 `llama\` 本身，所以现有安装什么都不用改。ini 里没有 `LlamaBackend` 时按 `vulkan` 处理。

## 三、顺带修掉的下载器 bug（两个都是真 bug）

1. **`download-llama.ps1` 下载不到东西**：它调 `/releases/latest`，而现在 llama.cpp 的 latest 是
   **semver 版本（v0.6.0）**，里面只有一个 `nightly-tag.txt`、**没有任何 zip** → 直接 `WebException`。
   这与用户实测一致（"CUDA 版下载失败"）。
   改法：拉 `releases?per_page=30`，取**第一个真正带 Windows 二进制包的 bXXXX 版本**
   （实测现在可用的是 `b11571`）；`-Tag` 仍可手动钉住。
2. **CUDA 版缺运行库**：CUDA 构建**还需要同目录的 CUDA 运行库**（`cudart64*.dll`），
   llama.cpp 把它单独发成 `cudart-llama-bin-win-cuda-12.4-x64.zip`。老脚本只下主包 →
   即使在 RTX 机器上，装出来的 CUDA 版也**起不来**。现在两个包都下，并在缺少 `cudart64*.dll` 时明确报错。

窗口内的"一键下载"是**进程内**实现的（`WebClient` + `ZipFile`），**不起 shell**：
拿设置里的路径去拼命令行属于把用户输入交给 shell，而且还要看那台机器的 PowerShell 执行策略。
每次请求都过 `GuardGithub()`：**只允许 https**，主机**白名单**（`github.com` / `api.github.com` /
`objects.githubusercontent.com`），字面 IP 里的回环/内网/保留地址一律拒绝。
（为此给两个构建脚本加了 `System.IO.Compression.FileSystem.dll` 与 `System.Management.dll` 两个引用。）
