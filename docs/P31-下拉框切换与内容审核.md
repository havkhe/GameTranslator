## 一、模型下拉框选了不生效（`ui/MainForm.cs`）

**症状**：在「翻译模型」下拉框里换一个模型，什么也没发生；再点「刷新列表」还会被拽回原来那个名字。

**根因**：下拉框**没有 `SelectedIndexChanged` 处理**。`_settings.ApiModel`（云端）与 `_settings.Model`（本地）
只在**刷新列表时**被写一次（`RefreshApiModels` / `RefreshModels`），此外没有任何地方记录"用户选了什么"。
而云端运行时交给管线的模型链是 `BuildModelChain()`，它只读 `_settings.ApiModel` ——
所以手动换的模型**从未进入模型链**。

本地路径之所以看起来正常：`StartLlama()` 是直接读下拉框当前项的（`Convert.ToString(_cmbModel.SelectedItem)`），
所以"选了再点启动模型"能生效；云端没有这个补救路径。

**改法**：

1. 给下拉框接上 `SelectedIndexChanged → OnModelSelectionChanged()`。
   - 云端模式：写入 `_settings.ApiModel`，日志打「云端模型已切换为 X（模型链 …，下一次开始翻译时生效）」。
   - 本地模式：写入 `_settings.Model` 与 `_runner.Model`。
   - 占位行（`（…）`开头的提示行）忽略；云端模式下选中**非文本模型**会被拒绝并回退，日志说明原因。
2. 新增 `_suppressModelChange`：程序化填充（每次刷新都会 `Items.Clear()` + 重新 `SelectedIndex`）不算"用户选择"，
   否则每次刷新都会把自动选中的第 0 项当成用户的选择写进设置。
3. `RefreshApiModels()` 的两处老毛病一起收掉：
   - **取不到列表时不再变死路**：以前填一行「（云端：还没有填 API Key…）」并**禁用**下拉框 —— 表现就是"无法切换云端模型"。
     现在改用**已配置的模型链**（`ChainModelIds()`：选中项在前、去重、排除非文本模型）填充，可正常选择；
     只有当模型链也为空时才回落成提示行。
   - **不再静默改掉用户配置的模型**：接口列表里没有 `_settings.ApiModel` 时，以前会落到第 0 项并把它写进设置；
     现在把配置的名字插到列表首位并选中（接口列表可能不全；真的不认识的名字由请求时的换模型逻辑兜底）。
4. `_cmbModel.Enabled` **去掉 `!_running`**：模型是在"开始翻译"时通过环境变量交给管线的，
   运行中改它只影响**下一局**，不会打架（日志已写明「下一次开始翻译时生效」）。以前运行中禁用，读起来正是"模型无法切换"。

## 二、`data_inspection_failed` 是什么

日志里那条：

```
REQUEST_FAILED "{"message":"Output data may contain inappropriate content. ...","code":"data_inspection_failed"}"
```

是**阿里云百炼的服务端内容审核**拦下了模型**输出的译文**（不是我们的 bug、不是模型或网络问题；HTTP 400）。
官方错误码页的说明是"输入或输出数据中含不适宜内容"，处置只有两条：「修改输入内容后重试」与「**如需内容加白，请联系客户经理**」——
**没有任何请求参数可以关闭它**（没有 `dataInspection` 之类的开关）。

### 实测（`inspect-rate.js`，用本机《牧场Ver1.1》的真实对白，逐条单请求走出货的 `client.js`）

```
24 条最长的日文对白：通过 23 / 拦截 1  → 拦截率 4%   重试通过 0
```

- 唯一被拦的那条是**露骨的性描写用词**（`ディルド` / `オナニー` 那类）；
- 满屏 `❤︎ ‼︎` 的拟声呻吟句（这次样本里绝大多数）**全部通过** —— 它拦的是**明确的性词汇**，不是气氛描写；
- **重试同一条仍然被拦**（确定性，不是随机抽样）→ 所以"给这条自动重试"没有价值。

### 在我们管线里的表现

走 `ask()` 的普通失败分支：该条记进 `-failures.json` 的 `request-failed`；批次会被拆小重试（也是同一条内容，仍被拦）。
它**不会**触发换模型（审核是服务级的，换模型没用），也**不会**损坏缓存或丢进度 —— 其余条目照常翻译。

### 可选处置（按推荐顺序）

1. **接受这 ~4%**：跑完后用**本地模型**补这些条目（本地无审核）。当前行为就是这样，不需要改代码。
2. 这类游戏**直接走本地模型**（本来就是离线可用的）。
3. 换服务商 / 自建端点（没有这个审核）。
4. 向阿里云**申请内容加白**（官方给的唯一口子，需联系客户经理）。
5. 想让损失可见：可以把这类失败单独标成 `blocked-by-provider`，并在结束时打印
   「本次 N 条被服务商内容审核拦下，建议用本地模型补」——**尚未实施**，等确认要不要。
